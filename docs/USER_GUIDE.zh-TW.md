# OpenCam 完整使用說明（繁體中文）

> 本說明適用於 OpenCam v1.2.0，包含錄影、加入影片、剪輯與輸出。

## 螢幕註記

開始錄影後開啟「螢幕註記」，可使用畫筆、直線、箭頭、方框與圓圈標示目前畫面，並選擇顏色與粗細。按住滑鼠左鍵繪製；橡皮擦可按住左鍵拖曳，移除碰到的整筆註記。工具列也提供復原、重做及清除全部。

預設 F10 開啟或關閉畫筆，關閉畫筆不會清除筆跡；F11 顯示或隱藏工具列；繪圖畫面或工具列有焦點時，Esc 結束繪圖並清除筆跡。快捷鍵可在「設定 → 全域快捷鍵 → 螢幕註記快捷鍵」調整；既有快捷鍵會保留，請以設定畫面為準。

工具列可拖曳移動或收合，並可能與註記一起錄入影片。筆跡固定在螢幕位置，不會跟隨教材捲動；錄入影片後無法後製移除。正式錄製前建議先短錄確認。

## OBS 錄影核心

Windows 與 macOS 正式錄影改用 OBS／libobs，針對舊流程影音不同步、實際 FPS 偏低與卡頓改善擷取及時間軸。FFmpeg 仍用於聲音試錄、預覽、剪輯與輸出，不作錄影備援。效能依硬體、解析度及負載而異；首次啟動預設 20 FPS，升級保留既有設定。

## 熟悉的使用方式：快速上手

OpenCam 結合 oCam 簡單易用的錄影概念，以及 EverCam 製作數位教材的工作流程。以下提供相近體驗的設定方式，讓熟悉這兩款工具的使用者快速上手。

### oCam 使用者：錄完自動產出影片

oCam 是輕巧好用、錄完即產出影片的工具。若希望類似體驗，勾選「停止錄影後自動輸出 MP4」，停止後等待自動輸出完成；亦可手動匯出 GIF（沒有音訊）。OpenCam 另外保留專案與 MKV 原始素材，方便續錄及編輯。

### EverCam 使用者：分段教學與剪輯

1. 錄製前新增錄製專案，命名並確認保存位置。
2. 游標樣式選「虛擬教鞭」，再選樣式與大小。
3. 開始錄影，可暫停／繼續，或停止後再開始，程式自動分段。
4. 「編輯錄製內容」可分割、合併、修剪、重排，並匯入多重 SRT／VTT 字幕。
5. 輸出 MP4 或含章節、字幕與逐字稿的網頁播放器。

教鞭提供暖白橙端、藍綠銀白、圓頭短棒與高對比黑金，各可選較小／標準／加大。效果直接錄入影片，事後不能更換；正式講解前先短錄並回放，確認畫面、聲音與同步。上述是相近工作流程，不代表與 oCam／EverCam 專案格式相容或具關聯。


oCam、EverCam 名稱及相關商標屬各自權利人所有；此處僅作使用方式說明，無合作或背書關係。

## 網頁播放器：閱讀設定與逐字稿下載

輸出的網頁播放器保留原有版面與 CC 字幕設定。切換右側「逐字稿」，預設保留語言與搜尋，按右上角「閱讀設定」才開啟設定浮層，調整跟隨播放、閱讀字級（100–200%）、行距、深色高對比／暖白背景，或下載完整逐字稿。浮層不占用逐字稿高度，可按關閉、Esc 或點外側關閉；手機和平板上可在浮層內捲動。重新開啟網頁時預設關閉。這些設定只影響閱讀清單，不改影片或字幕原檔；瀏覽器允許時會記住偏好，也可重設。

選擇逐字稿語言後，可下載完整的閱讀版 HTML 或 UTF-8 TXT；搜尋及清單目前載入的段數不影響下載內容。「下載含時間標記」預設關閉。HTML 保留章節、段落與語言，可離線閱讀、放大或列印；不需要影片檔也可開啟。沒有附加字幕時不會產生空白逐字稿。下載檔若含私人內容，請自行確認分享對象。

鍵盤可使用 Tab／Shift+Tab 移動、Enter 操作按鈕；影片區的空白鍵播放／暫停，左右鍵跳轉5秒，F 切換全螢幕。章節／逐字稿分頁支援左右鍵及 Home／End。Esc 或「關閉設定」關閉 CC 選單並返回按鈕。輸入搜尋時不觸發播放快捷鍵；正在操作逐字稿列時，跟隨播放不會替換該列或搶走焦點。播放器下方有鍵盤說明。

依 [W3C 逐字稿指引](https://www.w3.org/WAI/media/av/transcripts/)，字幕轉出的文字仍需作者確認說話者、重要非語音聲音、畫面文字與必要視覺描述；程式不會自行補寫或推測。可在下載後補充。閱讀與鍵盤功能不等於每一份教材已自動符合所有無障礙要求。

## 錄前音訊確認

「設定 → 錄影品質與行為 → 錄製前確認聲音」可選擇：

- **關閉**：開始錄影與暫停恢復時都不顯示聲音確認。
- **僅開始錄影時（預設）**：按「開始錄影」時確認聲音，暫停後繼續錄影時略過。
- **開始錄影及暫停恢復時**：開始錄影與每次暫停恢復前都確認聲音。

新增或插入一段錄製視為新的開始。聲音確認只檢查音訊，不擷取或顯示錄影範圍。關閉確認或未選音源時仍顯示錄製準備，並執行必要的權限、專案與輸出檢查。

滑鼠停在時間軸的紫色重點旗標上，可查看完整重點名稱；移開即隱藏，點擊仍定位至該重點。重點不改寫原始影片。

## 麥克風無聲或音量過低提醒

設定中的「麥克風持續無聲時提醒」預設開啟。錄製麥克風時，連續收到 30 秒無聲音量資料才提示；系統聲音不影響此判斷。恢復聲音、暫停、停止、停用麥克風或關閉提醒會清除提示並重新計時。讀不到音量資料不視為無聲，仍顯示原本的音量不可用狀態。

提醒不發出聲音、不搶焦點，也不會暫停、停止或重啟錄影。Windows 10 2004 以上在支援擷取排除時使用半透明浮窗，否則使用程式內提示；macOS 使用程式內提示。若把 OpenCam 程式本身放在錄製範圍內，程式內提示可能被錄入。

## 錄製啟動與重點標記

本版已移除倒數及設定選項，舊設定中的倒數秒數不再生效。確認錄前檢查後直接準備正式錄製；編碼器仍需要初始化，請等主畫面顯示「錄製中」才開始講解。

錄製中可按「標記重點」或預設 Ctrl+Shift+M；可在設定修改組合鍵。Windows及macOS使用全域重點快捷鍵，註冊失敗會提示，仍可用按鈕。macOS的開始／停止、暫停／繼續使用前景快捷鍵。若快捷鍵無反應，請檢查是否被其他程式占用，或改用按鈕。

編輯器上方「重點標記」清單可點選跳轉、改名與刪除；紫色旗標顯示目前時間軸位置。重點自動保存在專案內 `opencam-bookmarks.json`，不改影片、不升專案格式，也不自動加入網頁章節。改名／刪除不納入片段復原／重做。裁掉內容的旗標暫時隱藏，復原剪輯可再顯示；「—」表示尚未對應或該位置已裁掉。請整個專案資料夾一起保留，舊版本不提供重點操作。

### 音量控制與混音試聽

系統音訊、麥克風各有 0–100% 音量滑桿（預設 100%）及調整後的即時音量表，下方另顯示實際混音音量。先播放要錄的系統聲音並正常說話，降低過大的音源；不改變作業系統、喇叭或其他應用程式音量。音量為零、無聲或音量過低、等待資料與過載會分開提示。

五秒試錄完成後回放確認比例，並非即時耳返。更改滑桿會停用舊試錄，請重新試錄才能聽到新設定。確認並開始錄影才儲存音量，取消不儲存；下次開始及暫停續錄沿用已儲存設定。未啟用的音源不能調整。

仍錄成一條混音音軌，剪輯器的片段音量會調整整段混音，不能在錄完後分開調整系統音訊與麥克風。

## 聲音檢查操作

開始新的錄製、追加錄影或編輯器插入錄製前，先確認專案名稱／未儲存修改，再查看獨立的麥克風、系統音訊音量表。聲音檢查與五秒試錄皆為選用，可直接按「確認並開始錄製」；未試錄、未偵測到聲音或聲音檢查失敗都不會要求先通過測試。提示會指出沒有聲音的音源；未播放聲音時，系統音訊無聲屬正常情況。停用的音源不顯示無聲提醒。「等待音訊資料」與「無法讀取」仍如實顯示，不代表已確認收音成功。音源卡片下方有獨立狀態區呈現進度。

檢查與試錄只監看主畫面已勾選的音源；未勾選時明確顯示「本次不會錄製」，不顯示音量條或收音引導。若需要該音源，返回主畫面勾選後重新開始。五秒試錄期間，已選音源顯示試錄引擎實際收到的即時音量；完成或回放時停止即時監測。讀值不存在或過期不代表正常收音，仍應回放確認。

即時檢查只啟動已選音源，不保存檔案。五秒試錄先顯示啟動中，音訊引擎確認開始後才計時，接著顯示準備回放，驗證完成後才可播放。試錄為獨立暫存 PCM 音訊 MKV，沒有影片軌，不加入專案，也不驗證螢幕擷取或影片編碼器。回放只播放完成啟動後的最後五秒，並停止輸入監測，避免把回放當成收音成功。混合音軌不能取代兩個獨立音量表。回放後可直接開始正式錄製，也可自行選擇「重新檢查」。

按下確認後，視窗會顯示錄製準備進度，正式開始時自動關閉。準備期間請稍候，避免重複操作；如需結束，可使用主畫面的停止／安全結束。若顯示「無法開始錄製」，可按「關閉」，再依主畫面的錯誤提示處理。

取消／關閉會停止並清理試錄。請等音訊擷取與回放停止後再開始正式錄製。暫停恢復時是否顯示聲音確認，依「錄製前確認聲音」的選項決定；預設直接恢復。錄影期間若更換裝置或權限，請留意音量與狀態提示。

## 專案與剪輯

### 主畫面與專案流程

1. 沒有開啟專案時，按「開始錄影」會先詢問名稱並預填日期時間；確認後建立專案及錄影，取消不錄影。
2. 已開啟或重新開啟專案時，按「開始錄影」會往末尾增加片段。首次啟動預設開啟「停止後自動輸出 MP4」，之後記住選擇，新專案套用偏好，既有專案保留自己的設定；關閉後停止只保存內容，之後可手動輸出。
3. 主畫面提供「新增錄製專案」（只建立，不立即錄影）與「開啟錄製專案」（選擇 `project.opencam`），並顯示目前專案名稱及片段數。
4. 暫停保存後或停止封裝完成後，可按「編輯錄製內容」。編輯器只負責剪輯、儲存專案與輸出 MP4，返回主畫面不會關閉目前專案。
5. 錄影中禁止進入編輯器、新增或開啟專案。暫停時可以編輯，但必須停止錄影後才能切換專案。編輯器開啟時鎖定主畫面；請先返回主畫面再繼續錄影，返回及關閉均會詢問如何處理未儲存修改。
6. 「專案已儲存」只表示剪輯資料已保存，不代表已輸出最新 MP4。請保留整個專案資料夾及其來源素材，不要只搬移 `.opencam` 檔。

Windows 下載與免安裝使用步驟請見 [README](../README.md)。錄製內容可暫停、繼續、剪輯與儲存，重新開啟後也可追加錄影，再選擇需要的格式輸出。

### 剪輯、預覽與儲存

- 點選左側片段或時間軸片段進行選取；兩處均可拖曳排序，拖曳邊緣不會裁剪長度。用時間軸定位，再於播放頭分割，或刪除選取範圍／整個片段。可用復原／重做修正操作；先前已儲存的誤裁片段不會自動還原。
- 右側屬性可改片段名稱、音量（0–200%）、靜音、淡入／淡出、裁切、縮放與位置；有效修改會自動生效，另按「儲存」保存專案版本。標題旁鉛筆可改專案名稱；改名不移動資料夾或來源 MKV。
- 預覽可播放／暫停、跳轉時間，選擇預覽畫質，調整預覽區大小及全螢幕。預覽聲音只有開／關，沒有獨立音量滑桿；此開關不改輸出聲音。原始畫質選項受影格記憶體限制，預覽畫質不改變輸出設定。
- 按「儲存專案」才把剪輯當作已儲存版本。復原草稿是中斷保護，不等於已儲存，也不等於最新 MP4。切換／關閉流程遇到未儲存修改時可選儲存、捨棄或取消；重開遇到復原草稿時可選是否復原。
- 手動輸出前依提示處理未儲存修改。若相同內容已有可驗證的輸出，可開啟既有結果、重新輸出或取消。輸出有進度及取消控制；取消／失敗不應刪除原始素材。

## 加入影片

1. 開啟專案，進入「編輯錄製內容」；空白專案也可以加入影片。
2. 按左側「加入影片」選擇一個或多個檔案，或從檔案總管／Finder 拖入左側片段區。
3. 等待檢查、複製或轉換及驗證完成。可取消目前與剩餘工作，已成功加入的片段保留。
4. 影片依序加到時間軸結尾，以原檔名命名，可重排、分割、修剪、合併、調整音量與匯出；儲存後可重新開啟。

支援 MP4／M4V、MOV、MKV／WebM、AVI，實際取決於內附解碼器。目前限單一影片軌、零或一條音軌、SDR，寬高不得超過 4096 像素；多音軌、PQ／HLG HDR 會提示不支援。內嵌字幕與章節不自動匯入，字幕另用 SRT／VTT 附加。

相容 H.264 優先重新封裝，其他支援素材依需要轉為 H.264／AAC，可能花費時間及影響畫質。素材儲存在專案 sources/，不修改外部原檔，匯入成功後不依賴原始路徑。專案畫布與 FPS 不變，尺寸不同時按比例縮放並補黑邊。多檔依選取器／拖放提供的順序處理；單檔失敗不撤銷先前成功結果。剪輯後請檢查既有字幕同步。

## 1. 系統需求與首次啟動

### 畫面擷取

Windows 與 macOS 使用 OBS／libobs 核心：Windows 使用 Windows Graphics Capture，macOS 使用 ScreenCaptureKit。正式版不使用 GDI 或 FFmpeg 錄影備援；啟動失敗時顯示原因並保留已寫入內容。可在主畫面查看實際擷取與編碼器。

選擇單一螢幕或位於同一螢幕內的矩形範圍。macOS 需允許螢幕與系統音訊錄製、麥克風權限；更改權限後重新開啟程式。高解析度、較高 FPS 及同時播放影片會增加負載，預設 20 FPS 是一般教學的起點；動態內容可試 30 FPS，先短錄回放確認。

### Windows 畫面擷取

Windows 錄影所需的 Microsoft Visual C++ 執行階段隨套件提供；安裝版安裝完成即可使用，免安裝版完整解壓即可執行，不需另外安裝編碼器或下載 DLL。若提示套件缺檔，請重新下載並完整解壓，不要單獨替換 DLL。

由 OBS 核心處理選定螢幕與音源，不需選 GDI／桌面擷取模式。顯示器配置或裝置變更前先停止錄影；若擷取中斷，保留專案與 MKV，依錯誤訊息處理，不要覆蓋原始素材。

### Windows

- Windows 10 或 Windows 11，x64。
- 安裝版與免安裝版都已包含執行所需元件。
- 在 [Releases](https://github.com/kaoshou/OpenCam/releases) 下載 `OpenCam_v1.2.0_Windows_x64_Setup.exe` 或 `OpenCam_v1.2.0_Windows_x64_Portable.zip`。檔名會標示版本、Windows 及 x64 架構。
- 系統音訊使用 Windows 音訊回送擷取；麥克風可在 OpenCam 中選擇。

### macOS

- macOS 13 Ventura 或以上。
- 官方版本目前支援 Apple Silicon（arm64）；尚未提供 Intel Mac（x64）版本。
- 在 [Releases](https://github.com/kaoshou/OpenCam/releases) 下載 `OpenCam_v1.2.0_macOS_arm64.dmg`；檔名中的 arm64 表示 Apple Silicon。
- 第一次啟動後，請到「系統設定 → 隱私權與安全性」允許 OpenCam 使用：
  - 螢幕與系統音訊錄製
  - 麥克風（需要錄製麥克風時）
- 權限變更後若沒有立即生效，請完全結束 OpenCam，再重新開啟。
- macOS 的麥克風來源是系統目前的預設輸入裝置。若要換麥克風，請先到 macOS「聲音」設定切換預設輸入裝置，再開始錄影；也可在暫停期間切換後再繼續錄影。

## 2. 快速開始

首次開啟提醒：目前未提供 Windows 發行者簽章或 Apple Developer ID 公證。若出現安全性提示，先確認下載來自官方 Releases；macOS 可參閱 [Apple 的安全開啟說明](https://support.apple.com/zh-tw/102445)。不要停用整體系統防護；若顯示損毀或惡意內容，請停止開啟並回報。

1. 在「錄製範圍」選擇「指定螢幕」或「自訂矩形區域」。
2. 選擇 FPS（5、10、20、30 或 40，預設 20）、編碼器與游標樣式；如有需要，先在偏好設定選擇預設畫質。
3. 決定是否錄製系統聲音及麥克風。
4. 確認儲存位置至少有 1 GB 可用空間。
   首次錄影前即可設定「停止錄影後自動輸出 MP4」，選擇會套用到新建立的錄製專案；開啟既有專案時則使用該專案的設定。
5. 點選「開始錄影」。從準備錄影開始，會立即鎖定不應再變更的選項。
6. 錄影中可暫停、繼續或停止。若需要變更音訊開關或游標樣式，請先暫停。
7. 點選「停止錄影」後，等待素材保存；自動輸出開啟時再等待 MP4 輸出完成。關閉自動輸出時，沒有新 MP4 是正常的，稍後可手動輸出。

錄影初始化、錄影或暫停期間若按下視窗關閉按鈕，OpenCam 會顯示提醒並取消關閉。請先停止錄影並等候封裝完成，再關閉程式。

若 UI 被作業系統強制結束或異常消失，背景 Recorder 會偵測父行程已離開，安全停止並收尾目前的 MKV，再嘗試完成封裝後退出；不會在 UI 消失後繼續無人監看的錄影。若封裝未完成，重開 OpenCam 後使用「修復救援」。

若啟動錄影後長時間無法確認狀態，OpenCam 仍會鎖定設定，但會允許按「停止」嘗試安全結束。若連安全停止都失敗，關閉提醒才會提供「強制結束…」，點選後還需再次確認。強制結束可能中斷 MKV 寫入；重新開啟後若沒有 MP4，請在原儲存位置使用「修復救援」。一般按 X 不會直接強制結束。

## 3. 錄影模式

### 指定螢幕

錄製所選顯示器的完整畫面。若電腦連接多個顯示器，可從清單中選擇其中一個。

不確定「螢幕 1／2／3…」分別是哪一台時，先選擇「指定螢幕」，再按螢幕清單右側的小型「辨識螢幕」圖示（滑鼠停留可看提示）。OpenCam 會短暫在每台已連接的顯示器上顯示對應編號，並特別標示目前選中的螢幕；不論連接幾台都依清單編號顯示。若顯示器位置或縮放設定無法可靠對應，OpenCam 會略過不確定的標籤並提示，避免標錯螢幕。辨識標籤不會進入錄影，開始準備錄影時也會關閉。

這裡的「完整畫面」是指所選的單一顯示器，不是把所有顯示器合併成一支影片。開始錄影後，顯示器來源會鎖定；如需更換顯示器，請先停止目前錄影。

### 自訂矩形區域

選擇此模式後，開啟選取框來指定實際錄製範圍。選取框內部是透明的，可看見即將錄製的內容。

- 拖曳框體可移動選區。
- 拖曳邊緣或角落可調整大小。
- 按 Enter 確認選區。
- 按 Esc 取消選取。

OpenCam 會將選區轉換成實際畫面像素，並在必要時調整成編碼器可接受的偶數尺寸。選區只能在尚未開始錄影時修改。

## 4. 錄影參數與主畫面選項

### FPS

- **5／10 FPS**：適合簡報、操作步驟及變動較少的畫面；首次啟動預設為 20 FPS。
- **20 FPS**：首次啟動預設，兼顧一般教學流暢度與負載。
- **30 FPS**：動態內容較多時可嘗試，通常需要更多資源。
- **20／40 FPS**：依畫面內容與電腦負載調整；40 FPS 的處理負載較高，不保證比 30 FPS 更流暢。

錄製選單不提供 60 FPS；舊偏好若為 60 FPS，會改為 30 FPS。既有專案與影片的幀率資料不會因此被改寫。

### 編碼器

- **自動**：建議選項。OpenCam 會優先選擇可用的硬體編碼器，若不可用則回退至 CPU 編碼。
- **CPU（libx264）**：相容性高，但通常使用較多 CPU。
- **硬體編碼**：依平台與電腦硬體，可能使用 NVIDIA NVENC、Intel QSV、AMD AMF 或 Apple VideoToolbox。

在「錄影狀態監控」查看實際使用的編碼器：

- **自動不保證硬體加速**：Windows 按 NVENC → QSV → AMF、macOS 按 VideoToolbox 依序驗證，第一個成功者才用於錄影。指定硬體失敗則回 CPU，不改選其他品牌。
- 在音量波形下方查看**實際編碼器**。開始前顯示「開始錄影後顯示」；開始後顯示 libx264 (CPU)、NVENC、QSV、AMF 或 VideoToolbox，改用 CPU 時會附上原因。
- **只有第一段尚未成功開始時**，硬體啟動失敗才容許一次 CPU 重試。首段成功後整場固定實際編碼器；暫停改音源或游標仍可繼續，但不能混用不同編碼器。續錄失敗時保留已錄片段與暫停狀態，可重試或按停止封裝；程式中斷後再使用修復救援。失敗候選檔不覆寫既有內容，也不加入正常合併清單。
- 若遇到啟動問題，可查看[應用程式日誌](#設定檔與應用程式日誌)。分享前請檢查日誌中的路徑或裝置資訊。

編碼器備援不會自動降低設定的錄影解析度、FPS 或畫質。

啟動失敗且程序已安全清理的未確認片段，保留在同一工作階段目錄的 `failed_attempt_*.mkv`，供診斷或專業人員手動檢視，不會自動接進正常／救援成品。若清理或移存失敗，會阻止下一次啟動；已確認片段與當機時尚未確認的工作檔仍保留原有救援機制。

### 畫質

- 畫質預設值位於偏好設定，會套用到下一次開始的錄影。
- **超高畫質（Ultra）**：畫面最清晰，檔案較大，編碼負載也可能較高。
- **標準（Standard）**：預設且建議的一般用途選項，在清晰度、負載與容量間取得平衡。
- **精簡（Compact）**：檔案較小，適合容量有限或長時間錄影，但細節較少。

不同編碼器採用不同品質控制方式，因此相同的畫質名稱不保證產生完全相同的位元率或檔案大小。

### 游標樣式

- **原始游標**：保留一般游標外觀。
- **虛擬教鞭**：位於選單第二項，使用透明背景的教學指示棒，前端對準滑鼠位置。
- **黃色光暈**：在游標周圍顯示醒目光暈。
- **光暈與點擊漣漪**：除光暈外，也顯示點擊回饋。
- **隱藏游標**：影片中不顯示游標。

### 教鞭錄製方式

選擇「虛擬教鞭」後，可在下方選擇四款樣式：暖白橙端（預設）、藍綠銀白、圓頭短棒、高對比黑金。大小提供較小、標準（預設）、加大，程式會記住你的選擇。錄影中鎖定設定；暫停後可修改，繼續錄影時套用到新片段，不會改動已錄製的內容。

Windows 與 macOS 均沿用既有錄影流程，即時顯示教鞭圖層並直接錄入影片，無須額外擷取開關。桌面保留正常滑鼠，操作時可能同時看到滑鼠與教鞭；圖層準備完成後，錄影擷取會省略原生游標，避免影片出現雙指標。

新錄影不再建立指標軌跡。教鞭已經是影片的一部分，預覽與匯出使用同一份影像，之後無法單獨更換或移除教鞭。圖層無法啟動時改錄一般游標；若圖層在錄影途中消失，會顯示提醒，但不會為了指標而重啟或中斷影音，該段後續可能沒有指標。

### 舊專案的後製指標

編輯器已移除「後製指標」按鈕；新錄影請在主畫面選擇教鞭。舊專案仍保留並讀取既有指標設定，不會刪除軌跡或改動來源影片。

備份或搬移時請保留整個專案資料夾，包含 `pointers` 軌跡檔。軌跡缺失或損壞時，預覽會回到原始影音並提醒；匯出不會自動略過損壞的指標，需先還原完整備份或用支援後製指標的舊版處理。此類舊專案格式為第 5 版，請勿用不支援此格式的程式開啟。

### 系統聲音與麥克風

兩個音訊來源可以獨立開關，因此支援四種組合：無音訊、只有系統聲音、只有麥克風，以及兩者同時錄製。

- **系統聲音**：錄製電腦播放的聲音。macOS 13 以上使用 ScreenCaptureKit。
- **麥克風**：Windows 可在 OpenCam 中選擇裝置；macOS 使用系統預設輸入裝置。

開始錄影後，音訊設定會先鎖定。若要改變系統聲音或麥克風開關，請先暫停，修改後再繼續；OpenCam 會從新的錄影片段套用設定。

錄影狀態區會分別顯示「系統聲音」及「麥克風」的即時音量波形，用來確認目前的輸入是否有聲音。這是最近音量的概略指示，不是音訊內容預覽或精準的音量表：

- **收音中**：該來源目前有可偵測的音量。
- **無聲**：正在監測該來源，但目前音量很低或沒有聲音。
- **關閉**：這段錄影未啟用該來源。
- **已暫停**：錄影暫停中，波形不代表正在錄音；繼續後會重新取得資料。
- **無法監測**：即時音量資料暫時不可用。這不等於已證實音軌無聲；若持續出現，請停止後檢查成品與音訊裝置。

波形僅讀取錄音管線產生的音量數值，不會額外保存原始音訊，也不會改變錄影內容。

### 儲存位置

- **開啟資料夾**：若已有完成的錄影，會開啟儲存資料夾並盡可能選取最近的成品；否則直接開啟資料夾。
- **變更**：選擇新的輸出資料夾，只能在閒置時使用。

變更儲存位置也會改變 OpenCam 搜尋修復工作階段的位置。若要救援以前儲存在其他位置的錄影，請先把儲存位置切回原本的輸出根目錄。

### 開始錄影時最小化

啟用後，正式開始錄影時會將 OpenCam 主視窗最小化，避免主視窗出現在錄製內容中。

## 5. 錄影、暫停與選項鎖定

點選「開始錄影」後，即使畫面仍顯示正在準備，OpenCam 也會立即鎖定錄影來源、顯示器、選區、FPS、編碼器、畫質、儲存位置及其他固定選項，避免使用者誤以為臨時變更會套用到正在建立的錄影。

錄影暫停後，只有以下項目可修改：

- 是否錄製系統聲音
- 是否錄製麥克風（以及 Windows 的麥克風選擇）
- 游標樣式

其他錄影設定仍會保持鎖定。繼續錄影時，OpenCam 建立下一個 MKV 分段並套用上述新設定；已保存的暫停片段也可進入編輯器。停止保存專案，並依每個專案的自動輸出選項產生 MP4。暫停本身不會結束整個工作階段。

## 6. 錄影機制與檔案安全

OpenCam 的介面與錄影引擎是分開的處理程序。目前專案的原始 MKV 保存在專案內；剪輯只修改配方，不覆寫來源。新專案包含：

```text
<專案資料夾>/
├── project.opencam
├── sources/
├── sessions/Sessions/<工作階段 ID>/  # MKV 分段及工作階段資料
├── cache/
└── exports/
```

每次暫停安全結束目前分段並保存，繼續時建立下一段。請備份整個專案資料夾；只複製 `project.opencam` 不包含來源影音。舊版非專案錄影仍可能位於 `<儲存位置>/Sessions/`，使用 `segment_*.mkv` 或 `recording.mkv`。

正常停止時的專案流程如下：

1. 通知 OBS／libobs 錄影核心安全停止並完成目前 MKV。
2. 檢查工作檔是否可讀。
3. 保存專案；若開啟自動輸出則輸出目前時間軸。相容完整片段可快速保留影片編碼，必要時轉碼音訊；修剪、效果、不相容串流或無法確認封包時序會重新渲染。
4. 使用 FFprobe 驗證 MP4。
5. 將成品以包含安全化專案名稱的檔名保存，不覆寫既有結果。請依輸出完成訊息查看實際位置。

專案原始 MKV 必須保留，後續重開、剪輯與續錄仍需要它們。舊版「成功封裝後刪除工作檔」設定不代表可以清除專案來源；不要因 MP4 已輸出就刪除專案內的 MKV。

### 磁碟空間保護

- 開始錄影前，儲存磁碟至少需要 1 GB 可用空間。
- 錄影中會定期檢查剩餘空間。
- 到達「警告門檻」時會提醒使用者。
- 到達「臨界門檻」時會嘗試安全停止，避免磁碟完全耗盡而損毀資料。

## 7. 偏好設定說明

### 一般與語言

- **語言**：繁體中文、English (US) 或日本語；適用於程式介面。
- **網頁播放器介面語言**：勾選匯出播放器可用的繁體中文、English、日本語，至少保留一種。預設可選「自動判斷（依瀏覽器）」或指定已啟用的語言；停用指定預設語言時改回自動判斷。只保留一種時，網頁不顯示語言選單。
- 播放器右上角可切換介面語言並記住選擇。自動判斷會將各種中文對應繁中，日文對應日文，其他未支援語言使用英文，讀不到語言時使用繁中。若對應語言未啟用，依英文、繁中、日文順序選用已啟用語言。
- 語言設定只套用至之後匯出的播放器，不修改既有資料夾；介面語言與字幕／逐字稿語言分開，切換介面不改變播放位置、搜尋內容或字幕選擇。
- **錄影完成後開啟資料夾**：MP4 成功產生後自動開啟輸出位置。
- **開始錄影時最小化**：與主畫面的同名選項相同。

### 快捷鍵

預設快捷鍵：

- Ctrl + F9：開始／停止錄影
- F9：暫停／繼續錄影
- F10：開啟／關閉畫筆（保留註記）；F11：顯示／隱藏註記工具列
- Esc：結束繪圖並清除註記（繪圖畫面或工具列有焦點時）
- Ctrl + Shift + F1／F2／F3／F4：選擇畫筆／直線／方框／圓圈

上述快捷鍵可在「設定」修改；既有使用者的錄影快捷鍵會保留。

可用按鍵包括 F1–F12、R、S、P、Space、Insert 與 Home，並可搭配 Ctrl、Alt、Shift 及其部分組合。開始／停止與暫停／繼續不能設定成完全相同的組合。

> Windows 可使用全域錄影快捷鍵；macOS 的開始／停止及暫停／繼續需 OpenCam 視窗在前景。macOS 註記與重點快捷鍵依系統註冊結果，請以設定與提示為準。

### 預設畫質

設定新錄影預設使用「超高畫質」、「標準畫質」或「高壓縮節省空間」。已經開始的工作階段不會因為變更偏好設定而改變固定畫質。

### 成功封裝後刪除工作檔

此設定屬於舊版非專案錄影流程；目前專案來源必須保留，不因一次輸出成功而刪除。

舊版流程預設關閉；開啟會在成功封裝後清除非專案工作檔。目前專案的專案原始片段則保留。

### 磁碟警告與臨界門檻

- 警告門檻可選 1、2、5 或 10 GB；預設 2 GB。
- 臨界門檻可選 200、500 或 1000 MB；預設 500 MB。
- 警告門檻必須高於臨界門檻。若讀到無效或舊版錯誤設定，OpenCam 會回復 2 GB／500 MB 的安全預設值。
- 無論門檻如何設定，開始錄影仍固定要求至少 1 GB 可用空間。

### 關於本程式

顯示目前版本、授權資訊與 GitHub 專案連結。此頁不會改變錄影設定。

自 0.2.0 起，OpenCam 專案自有原始碼採用 [AGPL-3.0-or-later](../LICENSE)。下載包內的 `LICENSE` 是完整條款，`SOURCE.txt` 指向該下載包對應的原始碼版本。FFmpeg 等第三方元件維持各自授權；較早發布的版本不受此次授權變更追溯影響。

## 8. 成品、工作檔、設定與日誌位置

### 預設輸出位置

| 平台 | 預設位置 |
| --- | --- |
| Windows | `C:\Users\<帳號>\Videos\ScreenRecordings` |
| macOS | `/Users/<帳號>/Movies/ScreenRecordings` |

「變更」選擇新專案的建立根目錄及手動輸出目的地；目前開啟的專案仍保留原資料夾。專案原始片段在專案內的 `sessions/Sessions/`，舊版非專案錄影則在輸出根目錄的 `Sessions/`。

### 工作階段內容

目前專案的工作階段位於 `<專案>/sessions/Sessions/<工作階段 ID>/`；請保留整個專案。舊版非專案錄影才位於儲存根目錄下的 `Sessions/`。

```text
<專案>/sessions/Sessions/<工作階段 ID>/
├── session.json
├── segment_000.mkv
├── segment_001.mkv
├── recording.log
└── recovery.json        # 執行救援後才會出現
```

部分工作階段也可能有 `session.json.bak`。`.recovery.lock` 是救援期間避免多個 OpenCam 同時處理同一資料的暫時鎖定檔。

### 設定檔與應用程式日誌

| 類型 | Windows | macOS |
| --- | --- | --- |
| 設定檔 | `%LOCALAPPDATA%\ScreenRecorder\user_settings.json` | `~/Library/Application Support/ScreenRecorder/user_settings.json` |
| 日誌目錄 | `%LOCALAPPDATA%\ScreenRecorder\Logs` | `~/Library/Application Support/ScreenRecorder/Logs` |

不建議在 OpenCam 執行中手動修改設定檔。回報問題時，可一併提供相關工作階段中的 `recording.log` 及應用程式日誌，但請先確認其中沒有不希望分享的路徑或裝置名稱。

## 9. 修復救援何時使用

本節描述工作階段 MKV 的修復救援，不是剪輯草稿復原。中斷後先備份整個專案並重新開啟 `project.opencam`；草稿提示只復原剪輯。專案工作階段位於 `<專案>/sessions/Sessions/`，檢查救援時使用 `<專案>/sessions` 作為掃描根目錄；舊版非專案錄影才使用原儲存位置。成功救出 MP4 不等於專案剪輯已復原。

適合使用修復救援的情況：

- 錄影途中 OpenCam 或錄影核心異常中止。
- 電腦停電、重新啟動或被強制結束。
- 錄影停止時封裝被中斷，沒有產生最終 MP4。
- 重新開啟後，OpenCam 顯示有可救援工作階段。

不應使用的情況：

- 錄影仍在進行或暫停中。
- MP4 已成功完成，只是想剪輯或修理其他來源的影片。
- 想把修復功能當作一般影片轉檔器。

OpenCam 啟動時會掃描目前儲存位置下的 `Sessions`。為避免把仍在運作的錄影誤判為異常工作階段，最近 15 秒內仍有心跳的工作階段不會列入救援；異常結束後請重新開啟程式並稍候片刻。

### 使用修復救援

1. 確定沒有任何錄影仍在執行。
2. 若原錄影使用自訂儲存位置，先將 OpenCam 的儲存位置切回該資料夾。
3. 等待 OpenCam 完成掃描；若找到內容，主畫面的「修復救援」會顯示可處理數量。
4. 點選「修復救援」，並等待所有工作階段處理完畢。
5. 救援成品會放在輸出根目錄，名稱為 `Recovered_<工作階段 ID>.mp4`；若檔名重複會自動加上序號。

救援會先檢查各 MKV 分段，跳過空白、損壞或無法讀取的項目，再嘗試串接所有有效內容。若完整串接失敗，OpenCam 會逐步移除損壞的尾端分段，盡可能救回前面連續可讀的部分，因此結果可能標示為「部分救回」並缺少最後一段內容。

修復救援不會刪除原始 MKV。即使 `session.json` 遺失或損壞，也會嘗試由現存分段重建必要資訊。

## 10. 手動找到並保全錄到一半的檔案

目前專案請先備份整個資料夾，工作階段在 `<專案>/sessions/Sessions/`。以下 `<原儲存位置>/Sessions/` 是舊版非專案路徑。

若 OpenCam 尚未顯示可救援項目，或你想先備份資料：

1. 確認 OpenCam 與錄影引擎都已停止；不要在錄影仍執行時移動工作檔。
2. 開啟 `<原儲存位置>/Sessions/`。
3. 找到對應時間的工作階段資料夾。
4. 將整個資料夾複製到另一個安全位置。保留 `segment_*.mkv`、`session.json`、`recording.log` 與其他檔案，不要先改名或覆寫原檔。
5. 重新開啟 OpenCam，把儲存位置設回原輸出根目錄，等待超過 15 秒後再執行「修復救援」。

最後一個 MKV 可能因異常中止而無法單獨播放，但不代表前面的分段都遺失。除非熟悉 FFmpeg 串接、時間戳與音訊軌一致性，否則建議先讓 OpenCam 自動救援，不要直接修改原始片段。

若仍找不到可救援內容，請依序確認：

- 儲存位置是否為當時錄影使用的原輸出根目錄。
- 是否已在異常結束後等待至少 15 秒或重新啟動 OpenCam。
- `segment_*.mkv` 或舊版 `recording.mkv` 是否存在且檔案大小大於 0。
- `recording.log` 與應用程式日誌是否記錄磁碟、權限、FFmpeg 或裝置錯誤。

## 11. 常見問題排除

### 無法開始錄影

- 確認輸出資料夾存在且可寫入。
- 確認磁碟至少有 1 GB 可用空間。
- macOS 請確認螢幕錄製權限，變更後重新啟動 OpenCam。
- 降低為 20 FPS、標準畫質並使用自動編碼器後再試。
- 查看應用程式日誌中的 FFmpeg 或編碼器錯誤。

### macOS 沒有系統聲音或麥克風

- 系統聲音需要 macOS 13 以上及「螢幕與系統音訊錄製」權限。
- 麥克風需要「麥克風」權限，且使用 macOS 當下的預設輸入裝置。
- 若聲音斷續，先使用 20 FPS、標準畫質與自動編碼器降低系統負載，並確認預設輸入裝置連線穩定；若仍發生，保留日誌與測試影片以便診斷。

### 停止後沒有看到 MP4

- 先檢查目前專案是否關閉「停止後自動輸出 MP4」；關閉時停止只保存專案，請手動輸出。

- 停止後仍需要時間完成驗證與封裝，長錄影或多分段錄影會較久。
- 不要在封裝期間強制結束程式。
- 檢查輸出根目錄與對應的 `Sessions` 資料夾。
- 若封裝被中斷，重新啟動後使用修復救援。

### 自訂區域無法調整

- 只有在閒置狀態且選擇「自訂矩形區域」時才能重新開啟及調整選取框。
- 點選開始錄影後，選區會立即鎖定；請停止後再修改。

### 「開啟資料夾」沒有反應

- 確認設定的輸出路徑仍存在且目前帳號可存取。
- 若路徑位於已拔除的外接磁碟或網路位置，先變更到本機有效資料夾。
- 查看狀態列與應用程式日誌中的開啟失敗訊息。

## GIF 與單一片段匯出

### 僅調整音訊的快速輸出

相容完整片段、保留目前設定與原始解析度，且只調整音量、靜音或音訊淡入淡出時，可保留影片編碼、僅處理音訊，適用 MP4 與網頁播放器。修剪、影像效果或壓縮仍依需要重新編碼；不是所有影片都能快速輸出，GIF 不適用此加速。檢查及校驗仍需時間。

### MP4 匯出品質

選擇「輸出… → MP4」或單一片段的「匯出片段… → MP4」後，先設定品質，再選擇檔名。網頁播放器匯出也會先顯示相同設定，套用至其中的 `media.mp4`，再選擇輸出資料夾。

- 品質：保留目前設定（預設）、標準壓縮、較小檔案。
- 解析度：原始大小、最高 1080p、最高 720p；保持比例、不放大，直向影片對應直向尺寸。
- 接受設定後會記住上次選擇。保留目前設定沿用原有匯出策略；選擇壓縮或調整解析度會重新編碼，耗時可能增加，文字與細節可能較模糊。實際檔案大小依影片內容而異。
- 只影響匯出的影片，不更動來源、專案畫布、幀率或字幕；停止錄影後的自動 MP4 輸出維持原設定。

時間軸中的影片或音訊片段按右鍵，可選「更改名稱」、「刪除片段」，或展開「匯出片段… → MP4／GIF」。刪除是移除時間軸片段，不刪除原始素材，可透過復原還原。

原本影片與編輯視窗的「輸出…」選單在 MP4 下方提供 GIF。片段清單或時間軸右鍵後，將滑鼠移到「匯出片段…」即可展開 MP4／GIF 子選單。只輸出該片段保留的範圍；合併片段包含全部子段，不會連帶輸出群組內其他片段。MP4 保留適用的聲音與效果，GIF 沒有音訊。

GIF 可選最大寬度 480／640／960／原始大小及 10／15／20 FPS，預設 640／15，保持比例、不放大並循環播放。沒有長度上限；達五分鐘會再次警告耗時、檔案大小與無音訊，仍可繼續。長片及高解析度素材需要大量暫存磁碟空間。匯出不修改原始素材、專案或字幕時間，也不燒入字幕。

MP4 與 GIF 都需使用新的輸出檔名。若選到已存在的檔案或資料夾，會提示「更換檔名」或「取消」；選好新位置後才開始匯出，既有內容會保留。若匯出途中失敗，請重新從選單選取格式與範圍。

## 12. 安全使用建議

- 重要或長時間錄影前，先做一段短測試並確認畫面、系統聲音與麥克風。
- 長時間錄影請保留足夠磁碟空間，並避免讓電腦自動睡眠。
- 錄影中不要強制關閉 OpenCam、拔除輸出磁碟或刪除 `Sessions` 內容。
- 專案原始 MKV 與匯入素材需保留；只要還要重開、剪輯或續錄，就不要刪除。
- 錄影他人、會議、受著作權保護或機密內容前，請確認符合所在地法律與相關授權規定。

### 如何判讀錄影健康狀態

- 即時波形表示 OpenCam 收到音量樣本，但安靜環境下的平線不等於故障。
- 錄影剛開始、剛恢復或尚無足夠資料時，健康狀態可能為未知；這是保守判定，不代表已失敗。
- 狀態區出現「錄影狀態異常」時，代表工作檔/影格連續沒有進度、編碼器回報錯誤，或已選的音訊來源沒有可用樣本。先確認畫面與波形；若警告持續，請安全停止並保存 Session 與 Log。
