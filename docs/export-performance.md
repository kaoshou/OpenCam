# 匯出效能改善（2026-10-29）

## 本次範圍

- MP4 與沿用 MP4 匯出器的網頁播放器：完整片段只有音量、靜音或音訊淡入淡出調整時，符合相容性檢查即可複製原始 H.264 影片，只重新產生音訊。
- 單片段也可使用這條路徑，不會送入至少需要兩個輸入的 concat 操作。
- 仍需原始品質／原始解析度；有修剪、畫面效果、後製指標或不相容音源時，保留原有重新渲染流程。
- 重新處理的音訊明確指定 AAC 192 kbps，與原剪輯渲染路徑一致。
- 日誌新增同一 exportId 下各階段 elapsedMs 與總耗時、completed 狀態。不改動進度通知或錄影核心。

保留原始素材 SHA-256、影片封包內容／PTS 驗證、接點解碼檢查、取消及失敗清理、驗證後才發布正式檔案。

## 本機量測

環境：macOS 26.5.2 / arm64、.NET 8、Homebrew FFmpeg 9.0.1。不是 Windows 實機結果，也不是 Release 包內所有 FFmpeg 版本的驗證。

素材：12 秒、1920×1080、30 FPS、testsrc2 動態畫面及 440 Hz 音訊，H.264/AAC；完整保留片段、音量調為 50%。對照透過不提供串流介面的程序包裝強制走既有 Render 路徑，不修改素材或輸出品質。新路徑使用實際原生 macOS bound-handle media process。

先暖機一輪，之後三輪交替執行兩種路徑。計時包含來源檢查、處理、輸出驗證與正式檔案發布；另對每個輸出執行完整 FFmpeg 解碼，均 exit 0。

| 最終版本 | 第 1 輪 | 第 2 輪 | 第 3 輪 | 中位數 |
| --- | ---: | ---: | ---: | ---: |
| 舊 Render 路徑 | 2,344.2291 ms | 2,332.4165 ms | 2,341.5140 ms | 2,341.5140 ms |
| 保留影片、只處理音訊 | 585.8812 ms | 599.7149 ms | 595.6679 ms | 595.6679 ms |

此特定情境約為原先 25.4% 的耗時（減少約 74.6%，約 3.9 倍處理速度）。**不能推論所有專案都同樣加速**。有畫面效果／修剪的專案仍用既有渲染器，GIF 本次沒有加速變更。保留影片不是壓縮檔案大小的功能。

## 驗證與限制

- 測試先行：舊邏輯下 6 個策略案例及 6 個實際匯出案例因重新渲染而失敗，擴充路徑後通過。
- 實際媒體測試覆蓋單片段／兩片段、音量／靜音／淡入淡出、影片封包序列、影音 DTS 單調及結尾時間、解碼聲音能量、來源雜湊與暫存清理。
- 48 個匯出策略／串接測試通過，包含原有取消、驗證失敗與回到渲染流程案例。
- 最終修正後全方案回歸：Core 374 通過；Media 1,465 通過、23 略過、0 失敗（6 分 17 秒）。略過項目不視為通過。
- NativeOnly UI 建置通過；現有 CS8602、CS9113、AVLN3001 等警告仍存在，並非零警告建置。
- 未宣稱 Windows 實機、長影片／大型片段數效能、主觀聽感、所有實際錄影來源或硬體編碼品質已通過。CI 與測試包結果以對應工作流程及交付紀錄為準；未發布 Release。

## 硬體編碼評估

本機 `h264_videotoolbox` 的 1080p／30 FPS、30 幀、`allow_sw=0` 探測 exit 0；這只是啟動能力測試，不是最終 MP4 品質驗收。Windows NVENC／QSV／AMF 未在本次 Mac 環境實測。

維持目前軟體渲染器，下一階段才導入硬體匯出：需要各平台的品質參數對應、裝置實際探測、取消與失敗後安全重試，以及時間戳、畫質與音訊驗證。不能直接把 x264 CRF 值套在不同硬體編碼器上，也不能把編碼器列在清單中當成可用。

## 獨立審查與後續小項目

獨立唯讀審查未發現阻擋交付的正確性問題。審查提出的 AAC 位元率差異已用先失敗再通過的測試修正。

後續補強（本輪已完成程式與本機測試）：

- 保留原有 UI 階段，另以 CopyVideo、RenderAudio、Mux 子步驟記錄耗時。
- 每段使用不同的音量、靜音或淡入淡出設定，逐段檢查解碼音訊能量。
- 以結構化日誌檢查成功 completed=true，以及取消／驗證失敗 completed=false。
- 追加 20／30 FPS、五分鐘的 64×36 合成媒體，檢查原影片封包雜湊、9000／6000 影格、影音結尾時間、完整解碼與來源保全。這不等同五分鐘實體錄影或高解析度效能驗證。
- Windows 與 macOS 的 CI 新增匯出測試篩選；macOS 包裝工作亦使用實際包內 FFmpeg 執行匯出測試。CI 執行結果另行記錄，設定加入本身不代表已通過。
- 補強後本機全套回歸：Core 374 通過；Media 1,467 通過、23 略過、0 失敗；打包／CI 腳本測試 77 通過、2 略過；NativeOnly 建置通過。沙箱內 AppKit 測試曾 SIGABRT，允許原生系統服務後重跑全部打包測試通過；不將環境失敗隱藏或視為產品已通過。
