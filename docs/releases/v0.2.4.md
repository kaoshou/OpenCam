# OpenCam v0.2.4

## English

- Bounded encoder probes drain process output, clean up timed-out probes, and reuse validated results. Auto prefers a validated hardware encoder but is not a guarantee of hardware acceleration.
- The recording status panel shows the actual encoder and CPU fallback reason. Pause/resume keeps the confirmed encoder for compatible segment concatenation.
- Improves startup failure handling and process ownership, fixes conflicting Windows output arguments, and preserves valid segments. Closed, unconfirmed failed attempts are kept as `failed_attempt_*.mkv` for diagnosis rather than appended by automatic recovery.
- Download filenames include version, operating system, and architecture. Packages are built by GitHub Actions, not local installers.

### Downloads

- `OpenCam_v0.2.4_Windows_x64_Setup.exe` — Windows 10/11 x64 installer.
- `OpenCam_v0.2.4_Windows_x64_Portable.zip` — Windows 10/11 x64 portable package.
- `OpenCam_v0.2.4_macOS_arm64.dmg` — macOS 13+ Apple Silicon; not Intel Mac.

### Validation limits

This remains an early 0.2.x release, not a declaration of Stable acceptance. GDI capture is unchanged: recording-time cursor flicker and Windows CPU improvements are **not established fixes**. Long-duration A/V sync, affected Windows hardware, full live audio/GUI acceptance, and forced-interruption recovery still require manual validation. Automated and synthetic-media tests do not replace those checks. See the [verification report](https://github.com/kaoshou/OpenCam/blob/v0.2.4/docs/verification/2026-09-29-encoder-diagnostics.md) and [manual checklist](https://github.com/kaoshou/OpenCam/blob/v0.2.4/MANUAL_TEST_CHECKLIST.md).

Existing IPC authentication, recovery path/overwrite protections, and macOS anonymous audio transport are retained. Signing/notarization is unchanged. The Windows third-party FFmpeg build's complete corresponding-source audit remains outstanding; this release does not claim that all security or licensing questions are resolved. Preserve original MKVs and session data awaiting recovery before updating.

## 繁體中文

- 編碼器探測加入時限、持續讀取輸出與逾時清理，重用已驗證的結果。「自動」優先使用驗證成功的硬體編碼器，但不保證硬體加速。
- 錄影狀態區顯示實際編碼器及 CPU 回退原因；暫停／繼續固定已確認的編碼器，維持分段合併相容性。
- 改善啟動失敗與程序清理處理，修正 Windows 輸出參數衝突，保留有效片段。已關閉且尚未確認成功的失敗候選保留為 `failed_attempt_*.mkv` 供診斷，不自動加入救援合併。
- 三個下載檔案均包含版本、作業系統及架構資訊，全部由 GitHub Actions 建置，不使用本機安裝包。

上列 Windows 檔案適用 x64；macOS arm64 適用 Apple Silicon，不適用 Intel Mac。

### 驗證限制

本版仍屬早期 0.2.x 版本，不代表完成 Stable 驗收。未更換 GDI 擷取，**不宣稱已修復游標閃爍或證實 Windows CPU 降低**。長時間音畫同步、發生問題的 Windows 實機、完整收音／GUI 操作及強制中斷救援仍須人工驗證；自動化與合成媒體測試不能取代這些檢查。詳見[驗證報告](https://github.com/kaoshou/OpenCam/blob/v0.2.4/docs/verification/2026-09-29-encoder-diagnostics.md)及[手動驗收表](https://github.com/kaoshou/OpenCam/blob/v0.2.4/MANUAL_TEST_CHECKLIST.md)。

保留既有 IPC 認證、救援路徑／防覆寫與 macOS 匿名音訊管線防護。簽章與公證狀態未改變，Windows 第三方 FFmpeg 建置的完整對應原始碼核對仍未完成；不宣稱所有安全或授權問題皆已解決。更新前請保留待救援的原始 MKV 與工作階段資料。
