# OpenCam v0.3.11

## 繁體中文

- 錄製前檢查改為只確認麥克風與系統音訊，不擷取畫面、不啟動影片編解碼，也不再顯示錄影範圍預覽。正式錄影仍保存原設定的畫面、編碼器與音訊。
- 五秒試錄改為純音訊暫存檔與聲音回放，不加入專案。先顯示啟動中，收到音訊引擎實際啟動確認才計時；停止、封存及驗證完成後才開放回放。
- 音源卡片下方新增獨立狀態區，清楚區分音訊載入、試錄啟動、五秒收音、準備回放與正式錄製準備。繁體中文與英文同步更新。
- 僅開啟使用者已選音源；未勾選的音源明示本次不會錄製。試錄期間顯示所選音源的即時音量，回放時停止輸入監測。缺失或過期資料不冒充正常收音；靜音與裝置錯誤分開處理。
- 關閉錄前檢查或未選音源時略過聲音確認，但仍顯示正式錄製準備，不略過權限、專案、輸出與實際啟動確認。開始、續錄及插入共用準備狀態。
- 確認後先停止檢查並釋放音訊裝置，再啟動正式錄製。實際開始前保留準備視窗；結果不明時維持保護，主畫面的停止與安全處置仍可操作，不以關閉視窗假裝取消已送出的錄製命令。
- 保留操作身分、版本、擷取租約、取消與停止確認；未新增應用程式套件或專案格式。

### 相容性與限制

- **純音訊試錄不驗證螢幕擷取或影片編碼器。** 正式錄製的重要場合前，請另以可拋棄素材檢查實際影片與聲音。試錄回放後需重新檢查音源才能確認開始。
- Windows／macOS 四種音源組合、不同速率的實體裝置、裝置拔除、慢啟動與停止、原生音訊回放及高 DPI 視覺仍需實機驗收。本機合成音源與 headless 測試不等於實機 PASS。
- 專案格式不變；字幕仍使用格式4，v0.3.3及以前不能開啟。請備份完整專案含重點附屬檔；字幕不燒入 MP4、不自動對時。
- 完整實體 Release Gate、長時間 A/V、GPU、多螢幕／游標、實際磁碟耗盡、瀏覽器離線／觸控／全螢幕、浮窗擷取排除與背景快捷鍵未全部完成。歷史 Windows 心跳／試錄／快速輸出偶發問題不宣稱全部根治。
- 套件未具可信發行者簽章或 macOS 公證；Windows FFmpeg 完整對應原始碼核對仍待完成。依使用者授權發布，不代表全部可靠性、安全、授權或實機驗收已通過；不宣稱 Stable 驗收完成。既有示範圖保留真實版本標示。
- 已知小幅介面待辦：啟動確定失敗時仍使用一般準備標題與取消按鈕文字；失敗說明、關閉操作及主畫面詳細錯誤可用。

## English

- Preflight now checks microphone and system audio only, without screen capture, video encoding/decoding or a capture-area preview. Formal recording retains the configured video, encoder and audio.
- Five-second trials use an isolated audio-only temporary file and audio replay, never a project clip. Startup is shown first; the timer begins after actual audio-engine acknowledgement. Replay is enabled only after capture stops, the file is sealed and audio validation completes.
- A separate area below the source cards distinguishes audio loading, trial startup, five seconds of capture, preparing playback and formal recording preparation. Traditional Chinese and English are updated together.
- Only selected inputs are activated; unselected sources explicitly say they will not be recorded. Selected-source levels are live during trials, and input monitoring stops during replay. Missing/stale samples are not reported as successful capture; silence remains distinct from device failure.
- Disabled preflight or no selected audio bypasses the audio check but still shows formal preparation. Permissions, project/output checks and actual start acknowledgement remain. Start, resume and insertion share preparation status.
- Confirmation stops checking and releases audio devices before formal capture. The preparation window remains until actual acknowledgement. Unknown startup remains protected while main-window Stop/safety controls stay accessible; closing a window cannot pretend to cancel a command already sent.
- Operation identity, revision, capture leases, cancellation and confirmed shutdown remain. No new application dependency or project-format change.

### Compatibility and limits

- **Audio-only trials do not validate screen capture or the video encoder.** Test actual video and audio with disposable material before important recordings. Recheck inputs after replay before confirming formal recording.
- Native Windows/macOS acceptance remains required for all four audio selections, differing device rates, unplugging, slow startup/shutdown, audio playback and high-DPI visuals. Synthetic/headless tests are not physical-device PASS.
- No project-format change. Subtitle projects retain format4, incompatible with v0.3.3 and earlier. Back up complete projects including bookmark sidecars; no MP4 subtitle burn-in or automatic retiming.
- The complete physical Release Gate, long A/V, GPU, multiple displays/cursor, physical disk exhaustion, browser offline/touch/fullscreen, advisory capture exclusion and background shortcuts remain incomplete. Historical intermittent Windows heartbeat/trial/fast-export issues are not claimed fully resolved.
- No trusted publisher signing or macOS notarization. Complete corresponding-source verification for Windows FFmpeg remains pending. Publication is user-authorized, not complete reliability, security, licensing, device or Stable acceptance. Existing illustrations retain their actual version labels.
- Minor UI follow-up: confirmed startup failure retains the general preparation heading and Cancel label; the failure explanation, dismissal and detailed main-window error remain available.
