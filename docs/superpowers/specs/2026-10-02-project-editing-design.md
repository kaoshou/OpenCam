# OpenCam 可續錄專案與輕量剪輯設計

日期：2026-10-02。狀態：待使用者審閱書面規格；未開始實作。

## 1. 目的與範圍

提供「錄錯可修剪、隔日可續錄、隨時可再輸出」的可靠錄影專案。使用者已確認：暫停與錄完後皆可預覽、刪除及剪輯；可重新開啟專案追加錄影；上方預覽、下方可縮放时间軸；產品仍以錄影為主，不做完整專業剪輯軟體。

第一版包含：單一影片時間軸與連動音訊、縮圖、精確定位、分割、頭尾裁切、刪除區間並接合、只保留區間、選取區間另存 MP4、片段拖曳重排、復原／重做、專案自動保存／重開、追加錄影後調整順序與完整 MP4 輸出。音訊隨影片同步剪輯及移動，不提供獨立音軌編輯。

不包含：直接在播放游標位置開始插入／覆蓋錄影、多片段群組拖曳、任意外部影片匯入、多軌、字幕、配樂、轉場、特效、變速、雲端協作、永久素材清理工具。補錄先追加至末尾，再以重排插入適當位置，不排除補錄內容的順序調整。先以 OpenCam 新建專案為支援對象。舊工作階段維持原救援流程，不自動改寫；只有 MP4 的舊成品不承諾恢復成可續錄專案。

最新使用者需求擴充了 AGENTS.md 的早期「不做剪輯」範圍。原有可靠性、MKV、程序隔離、救援與平台抽象規則仍適用。精確裁切所需的重新編碼僅用於專案輸出，不改變快速錄影的 stream-copy 原則。

## 2. 現況與架構決策

現況依據：`RecordingSession` 保存原始片段清單；`RecordingOrchestrator.PauseRecordingCoreAsync` 停止並釋放目前引擎；續錄產生新片段；停止直接 remux，並可依設定刪除 MKV。這不是剪輯時間軸或持久專案模型，不能直接把片段清單刪改成剪輯結果。

比較三案：

| 方案 | 優點 | 代價／判斷 |
| --- | --- | --- |
| 直接改写／刪除 MKV | 表面上簡單、省空間 | 難復原、可能破壞救援；不採用 |
| 原始素材＋非破壞式時間軸 | 編輯快速、可復原、保留錄影安全界線 | 需持久專案及專門輸出服務；採用 |
| 整合完整多軌剪輯系統 | 功能豐富 | 封裝、學習及回歸成本過大；暫緩 |

採用方案二：Project 包含多個 Recording Session，Session 包含不可變的已完成素材；時間軸引用素材範圍。編輯只改引用，不能改寫 Recorder 的事實紀錄或原檔。

## 3. 不破壞既有操作：快速錄影與專案入口

- 保留現有「快速錄影」為預設：停止後自動 MP4、既有刪工作檔設定只在此模式生效。
- 新增「新建錄影專案」「開啟專案」「最近專案」。建立時選名稱與專案位置，錄影前即建立持久容器，不等停止才保存。
- 專案模式：停止錄影只完成片段並保存專案，回到可編輯狀態；「輸出 MP4」是獨立按鈕，顯示上次輸出版本是否落後於目前編輯。
- 不在第一次停止時突然改變快速模式語意，也不把「保存專案」與「已輸出 MP4」混為一談。
- 專案模式永久保留素材；既有「成功封裝後刪除工作檔」在此模式停用並說明原因。介面分別顯示素材占用及輸出大小；刪除時間軸內容不宣稱釋放磁碟。

## 4. 編輯介面與精確操作

上方為等比例預覽（不拉伸），附播放／暫停、前後一格、目前時間／總長度及直接輸入定位時間。下方為時間刻度、縮圖片段與播放游標；可縮放、水平捲動、縮放至選區及顯示全片。右側片段列表可收合，依成品順序列出剪輯後片段與長度，附來源錄影標示；分割後為不同項目，不以檔名作主要操作介面。時間軸與列表共用同一份順序，來源錄製順序不因重排改寫。

- 點擊刻度或拖動游標只定位；拖動選取控制點只改選區，兩者顏色、命中範圍與標籤不同。
- 起點／終點按鈕與局部快捷鍵 I／O 設定選區；選區顯示起訖時間與長度。Space 播放；左右鍵逐格；僅編輯器有焦點且未輸入文字時接收，不搶全域錄影快捷鍵。
- 支援跨原始錄影片段選區。時間軸顯示剪輯後時間；需要時在片段資訊顯示來源時間，避免混淆。
- 磁吸至片段邊界與游標可關閉；放大時可精確選到畫格，不用滑鼠像素寬度決定實際精度。
- 「在此分割」不改變總長度；端點分割無效，不產生零長片段。
- 「刪除選取範圍」移除該區間並讓後段前移；一般刪除不彈確認，提供醒目的復原提示。
- 「只保留選取範圍」放次要選單，執行前告知會移除其餘範圍；「選取範圍另存 MP4」不改時間軸。
- 預覽選區，以及選定剪接點前後各 2 秒（不足時截至邊界）。播放跨接點不能偷播已刪內容。
- 刪掉全部內容可復原，顯示空時間軸；禁止空專案輸出，但仍可追加錄影。
- 初版縮圖必要；音訊波形是後續增强項，不以錄製時音量歷史假裝精確音訊波形。

### 片段重排與補錄定位

- 第一版一次移動一個時間軸片段；要移動片段中的一句話，先在起訖處分割，再移動中間片段。已裁切片段只搬動保留範圍，不重新帶回被刪內容。
- 片段標題／專用拖曳把手啟動重排，裁切把手只裁切，刻度／播放游標只定位。拖曳需越過最小移動距離才啟動，避免點擊變成搬移。
- 拖曳時顯示片段半透明預覽、醒目插入線及「移至某片段之前／片尾」。只允許插入片段之間或最前／最後，不覆蓋其他內容、不產生空白、不暗中分割落點片段。要插入某片段中間，先分割目的片段。
- 片段跟隨其全部音訊移動，其他片段自動讓位，總長度不變；來源檔及來源 in/out 不變。拖到原位置為無操作，不增加 revision／復原紀錄。
- 支援時間軸邊緣自動捲動；另有「往前一段」「往後一段」「移至最前／最後」及片段列表內拖曳，避免長片需要精細拖很遠。键盤操作僅在片段選取有焦點時生效，不與逐格／文字輸入衝突。
- 拖曳前停止預覽。放開有效落點後一次保存整個重排；Esc、拖出有效區或保存失敗皆保持原順序。成功後選中被移動片段並將播放游標移至其新起點，清除舊時間範圍選取，避免舊選區誤刪另一段。復原／重做恢復對應順序、游標與選取狀態。
- 重排後可預覽新接點；舊接點快取立即失效，未就緒時不得播放舊排序。預覽、縮圖列表、另存選區及 MP4 輸出全部依新順序。
- 新錄影仍以安全追加完成；在下一次可編輯狀態選中最新確認片段並標示「新錄製」。使用者可裁切後拖到前面或中間。多次暫停形成多段時，依個別片段逐一整理；移動後再續錄仍追加到當前成品末尾，而非游標位置。
- 例：原時間軸 A → B → C，補錄 D 後為 A → B → C → D。將 D 拖到 B 前，得到 A → D → B → C。若 D 是取代 B，須再明確刪除 B，不採隱含覆蓋。

取捨：採「插入式重排」而非可留空白／覆蓋的自由軌道，降低誤刪風險；採「先錄完再排」而非錄製中寫入既有片段，維持原本錄影與救援界線。這是輕量單軌能力擴充，不引入多軌剪輯系統。

第一版性能目標（不是已驗證結果）：基準 Windows x64／macOS arm64、1080p30、2 小時／200 剪輯區間，熱快取定位回饋 p95 ≤ 300ms；冷定位超過 500ms 顯示載入，UI 操作仍可取消。精確畫面未到位時顯示定位中，不把舊畫面標為新切點。

## 5. 時間、剪輯與資料模型

ProjectDocument：schemaVersion、projectId、revision、名稱、輸出畫布寬高及有理數 FPS、Sessions、MediaAssets、TimelineClips、最近輸出紀錄。機器裝置 ID 僅屬錄影設定，不作可搬移素材的識別。

MediaAsset：不可重複 assetId、專案內相對路徑、來源 session／segment ID、大小及媒體探測結果（PTS 起點、duration、codec、timebase、音訊有無、尺寸／FPS）。未封閉與未驗證檔不得登錄為可編輯素材。

TimelineClip：穩定 clipId、assetId、sourceIn／sourceOut。順序由列表決定，成品位置由累積長度推導，不能另存一份可不同步的位置。區間採半開 `[in, out)`，精確整數 ticks／有理數轉換，不累加浮點秒；符合 0 ≤ in < out ≤ 可解碼素材末端。

MoveClip 命令以 clipId、目的邊界（另一 clipId 之前或列表末尾）及預期 project revision 表示，不使用拖曳開始時的陳舊索引；先移除來源再解析插入位置。目的不存在、revision 不符或狀態已轉為錄影時拒絕提交，保持原文件。整次操作原子更新 revision 與復原紀錄；不改 session.SegmentFilePaths。快取鍵含素材身分及範圍；跨接點快取另含相鄰片段順序／revision。

剪輯與輸出共用一份時間映射／規劃邏輯：定位從成品時間映射至來源 PTS；固定輸出 FPS 下選取落於輸出畫格邊界，來源取對應可解碼影格。掉幀或可變時序不能只按 nominal FPS 猜來源位置。前後逐格以成品畫格定義；音訊以相同邊界換算樣本，不逐次四捨五入累積誤差。

編輯命令一次完成全部相關區間改動，支援逆向操作。復原／重做限本次開啟期間，最多保留 100 次；重開恢復最新已保存結果，而非承諾永久編輯歷史。新錄影加入屬不可刪除的素材事實，不因復原改寫 session。

## 6. 專案格式、保存與安全

專案採自包含資料夾，內含 `project.opencam`（版本化 JSON）、`sessions/<session-id>/`（現有 session.json／MKV／日誌）、可重建 `cache/`、以及預設 `exports/`。開啟的是 project.opencam；備份／搬移須整個資料夾。第一版不壓成單一大型專案壓縮檔、不跨專案共用素材。

- 唯一 project writer 使用 OS 排他鎖；第二個程式只能唯讀檢視，不以 PID 字串或刪 lock 檔搶鎖。UI、Recorder 不可同時寫 project manifest。
- 單一 writer 由 UI 的專案服務持有。Recorder 繼續只寫自己的 session 與片段；UI 退出時不連帶終止錄影，重開／恢復時由 session 事實補登尚未註冊素材，ID 去重且不得復活已排除的時間軸內容。
- 一次編輯先計算候選 revision；以同目錄暫存、flush、原子替換與前版備份提交。保存成功才更新已保存標誌與可繼續錄影資格。失敗顯示原因、保留最後有效文件與素材，不能把未落盤變更冒充已保存。
- 重開若主文件損壞，提出從有效備份恢復；若所有專案中繼資料遺失，只能另建「未剪輯救援副本」，不得聲稱重建了未知剪輯。
- 路徑必須綁定專案根目錄、拒絕 traversal／symlink／reparse 逃逸與輸出指向原素材。沿用既有安全路徑規則，不直接信任 JSON 或歷史絕對路徑。
- 缺檔保留缺失標記及時間軸，不靜默略過。第一版不提供自動搜尋替換；提示恢復正確素材、唯讀檢視或移除相關區間後再輸出。被替換／改變的檔案需重新驗證，不沿用舊快取。
- 新版 schema 用舊程式開啟時拒絕寫入；不以預設值覆蓋未知欄位。第一版以本機檔案系統為支持範圍，NAS／同步資料夾並行編輯不在驗收承諾內。

## 7. 暫停、停止、續錄與互斥

| 狀態 | 預覽／剪輯 | 輸出 | 錄影操作 |
| --- | --- | --- | --- |
| Preparing／Recording／Pausing／Stopping | 禁止 | 禁止 | 沿用狀態機有效操作 |
| Paused 且目前片段已關閉驗證 | 允許 | 第一版禁止；先停止本次錄影 | 繼續或停止 |
| 專案閒置、已保存 | 允許 | 允許 | 末尾追加 |
| Exporting | 第一版鎖定編輯／播放 | 可取消，不能重複輸出 | 禁止追加 |
| 保存失敗／恢復處理中 | 僅允許安全檢視及恢復操作 | 禁止 | 禁止啟動新錄影 |

暫停不自動打開完整剪輯器；顯示「預覽上一段」「從成品移除上一段」「編輯」。上一段指最近已確認的錄影素材，快捷移除只排除該素材仍存在於時間軸的區間，不物理刪檔。

繼續前必須成功保存編輯、取消並等待縮圖／解碼工作、有界停止預覽音訊輸出、釋放預覽資源，再透過既有認證 IPC 啟動錄影。停止預覽未確認時不開始，避免系統音訊／麥克風重錄預覽聲音。無法保證外部播放器不被錄入，介面須區分此限制。

同一 session 暫停／續錄仍遵守固定 encoder／capture 規則。停止後或重開專案的「追加錄影」新建 session，重新驗證螢幕與音源，不嘗試沿用過期裝置。不同尺寸追加時先提示以保持比例加黑邊適配固定畫布，不裁掉內容；不默默更改全專案尺寸。第一段有效素材確定畫布／FPS；無有效素材前可重新選擇。

專案／編輯／輸出是独立於 Recorder 的狀態與服務；不將所有狀態塞入既有 RecordingState。錄影中按 X 繼續沿用禁止意外關閉的提醒；專案暫停想離開時需先「停止並保存專案」，不默認結束正在進行的錄影。

## 8. 預覽與輸出技術策略

### 預覽

候選主方案為 LibVLCSharp／LibVLC 播放已完成本機素材，外加既有 FFmpeg 產生受限縮圖、精確定位影格及必要的剪接點預覽快取。播放器原生 seek 不能單獨充當切點精確性的依據。先讀原素材；不為每次編輯重建整部影片。

**採用門檻先於產品整合**：Windows x64／macOS arm64 上驗證 Avalonia 嵌入、音畫播放、跨區間排除內容、精確影格定位、取消／關閉無殘留、原生相依封裝及授權標示。單純 seek 若無法確保接點不漏出已刪內容，使用同一剪輯規劃生成短預覽快取；未完成顯示準備中。門檻失敗停止並回報，不偷偷換播放器依賴或假裝已通過。這是待執行的技術驗證，並非已選定套件版本或宣稱原生支援已測過。

不選自製完整解碼／音訊時鐘播放器（维护風險高）；不選 WebView 作第一方案（平台媒體能力及本機路徑安全額外複雜）。媒體預覽以介面隔離，Core 不依赖播放套件。拖曳採最後請求優先、最多一個解碼任務；可視範圍延遲縮圖、記憶體及磁碟快取有上限且可清除。錄影時停止預覽／縮圖背景負載。

### 輸出

- 從已保存 revision 產生不可變 ExportPlan，含依時間軸順序排列的全部素材時間範圍、畫布、FPS、音訊規格、輸出模式；不能按來源錄製時間、檔名或 session 順序重新排序。匯出紀錄綁定該 revision，不只標示「專案已輸出」。
- 無裁切、使用完整且媒體參數相容片段時才允許 stream-copy 快速封裝；codec 名稱相同不代表必然相容，必須核對必要流參數／extradata、時間戳與音軌布局。
- 有任意裁切、缺音軌或跨 session 格式不相容時，使用精確重新編碼路徑，預設 H.264／yuv420p 與 AAC；只在需要時適配固定畫布／FPS及音訊取樣率。至少一段有音訊時對無音訊區間補靜音，全部無音訊則不製造音軌。
- 第一版優先可取消、可驗證的 CPU 精確輸出，不將錄影用硬體探測結果直接當作剪輯輸出能力。匯出前明示需要重新編碼、可能耗時並有畫質損失；不承諾 smart rendering／零損失精確剪輯。
- 新增專用 EditorExportService；不把裁切流程硬塞進原 StreamCopyRemuxer。批次規劃避免長影片產生超出命令長度的單一指令及一次打開無限素材；受控暫存與資源預算寫入實作計畫。
- 輸出先寫獨立暫存檔，再確認 FFmpeg 成功、ffprobe 流／時長／尺寸／音訊符合計畫，通過後移到新成品名稱。預設不覆寫既有 MP4；取消、空間不足或驗證失敗保留專案及旧成品。
- 復原或變更選區不會改動已產生 MP4。每次重新輸出使用不同檔名；區間另存不變更主時間軸。

## 9. 元件邊界與交付順序

1. **可行性資格驗證**：播放／精確定位／跨接點／平台封裝，記錄 PASS／FAIL／BLOCKED，不更動正式錄影路徑。
2. **專案資料與可靠性**：Core 的 Project／Asset／Clip／時間映射／編輯命令；Infrastructure 的專案存取、鎖、版本與恢復；先做故障注入測試。
3. **專案錄影整合**：以 ProjectCoordinator 接收 Recorder 已確認素材事件，處理暫停／停止／新 session 追加及獨立的模式政策；保留現有快速錄影測試。
4. **預覽與輕量剪輯 UI**：上方預覽、下方時間軸、片段列表、插入式重排與快捷操作；純時間軸邏輯先驗證，再接平台播放器。
5. **輸出與全流程驗收**：剪輯規劃、快速／精確輸出、錯誤保護、雙語使用說明及實機矩陣。

每階段各自寫實作計畫與驗收報告；任何已知資料遺失問題先修正，不堆疊下一階段。設計通過不等於批准立即執行上述全部工作。對應 ADR 在實作計畫階段依本文的「背景、方案比較、決策、代價」拆出，保持裁決一致。

## 10. 驗收標準

### 自動化

- 時間軸：分割／裁切／跨素材刪除、全刪、端點、零長／越界拒絕、復原／重做、來源與成品時間來回映射；數千次操作不累积時長漂移。
- 重排：前移／後移／首尾／相鄰／原位、單片段、已裁切片段、先分割再移動、跨 session 補錄；每次均驗證素材不變、音畫綁定、總長度與片段集合不變，且預览與輸出順序一致。覆蓋 stale revision、消失的落點、拖曳取消、保存失敗、重開與復原／重做；新片段登錄不得重置既有順序。
- 合成編號畫格＋定時音訊標記：30／60 FPS、非零 PTS、掉幀、不同音訊组合及跨接點；精確輸出時長誤差 ≤ 1 個輸出畫格，已排除的測試畫格不得重新出現。來源影格重採樣規則與預覽一致。
- 2 小時合成媒體多次剪輯後量測頭／中／尾音畫標記，偏移 ≤ 100ms 且無持續漂移；不是只看兩條 stream 的總長度。
- 保存失敗、原子替換各階段終止、備份損壞、素材確認後 UI crash、重複事件、缺檔、未知 schema、多開鎖、路徑逃逸及 symlink；不能覆寫素材或靜默重建錯誤剪輯。
- 匯出取消、FFmpeg 強制結束、磁碟不足、預存同名檔、輸出指向素材、播放器停止失敗；既有媒體雜湊保持不變，未通過驗證不能公開為成功成品。
- 完整 .NET／網站／版本／封裝及 IPC／救援安全回歸。快速錄影仍按原設定自動 MP4；專案素材不受快速模式清理設定影響。

### Windows／macOS 人工驗收

- 錄一段→暫停→刪一句→預覽接點→續錄→停止→輸出；隔日重開→追加→再剪→再次輸出，两次成品及原始素材均存在。
- 錄 A/B/C、補錄 D，裁切 D 後移至 B 前，預覽兩個新接點，輸出須為 A/D/B/C；保存重開後順序不變。再續錄 E 應接在 C 後。另測長時間軸邊緣捲動、列表及鍵盤重排、拖曳與裁切／定位不混淆。
- Windows x64、Apple Silicon macOS；滑鼠／鍵盤、不同 DPI、小視窗、中英文介面與 2 小時時間軸定位。
- 四種音源各 5 分鐘；預覽播放中按續錄時不錄入 OpenCam 預覽；錄影設備改變後提示重選，不能錄錯螢幕或默默失去音訊。
- 錄影、保存、預覽、輸出各階段故障注入；安全停止／恢復與既有長錄測試依 AGENTS.md 執行。
- 每項記錄環境、步驟、輸出、ffprobe、時序指標及日誌。無硬體或 GUI 的項目標記 BLOCKED，不以 CI 綠燈替代。
