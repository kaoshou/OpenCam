# OpenCam 錄影專案與編輯模式設計

日期：2026-10-08（Asia/Taipei）

狀態：操作方向已獲同意；本份書面規格待使用者審閱。不是已完成的功能、實作計畫或發布承諾。

## 1. 使用者目標與設計邊界

使用者需要從 OpenCam 主程式錄製內容，在多次暫停之間編輯，結束後繼續整理；關閉程式後，下次能開啟同一專案續錄、調整順序、精剪片段並重新輸出 MP4。

介面需專業、美觀、簡單，優先服務講解、示範與分段螢幕錄影，不做完整多軌影視剪輯器。參考圖片的價值分別是大預覽與時間軸，以及容易理解的片段清單；不照搬其品牌、圖示或密集工具列。

採用「片段清單＋單軌時間軸＋可收合屬性面板」。不用純清單限制精細定位，也不用多軌編排增加初學者負擔。

此次是全新設計，先前已放棄的 editing-preview 分支不是實作基底，不恢復、不合併。第一個設計交付是從主程式入口走完流程的高擬真可操作模型，明確標示模型；真正功能驗收必須使用實際錄影，不能由短合成片段試作取代。

## 2. 與既有產品的關係

現有本機主分支 VERSION 為 0.2.5。RecordingOrchestrator 暫停時停止並釋放當前錄影引擎，續錄建立新 segment；RecordingSession 保存片段路徑。停止後會拼接／Remux、驗證 MP4，並可能按設定刪除工作檔。

這些能力是整合基礎，不代表已有可跨次續編的專案。新增專案管理層不可把既有 session.json 直接當成永久剪輯專案，也不可改掉原本快速錄影的停止／救援保護。

- 快速錄影：保留現行錄製與 MP4 成品流程，預設選項、快捷鍵及平台擷取行為不因加入編輯功能改變。
- 錄影專案：首次儲存後持續保留素材、編輯內容和多次錄製工作階段，輸出影片是獨立動作。
- 主程式新增「新建錄影專案」「開啟專案」「最近的專案」入口；不是要求使用者尋找另一個 App。
- 舊 MP4 匯入與舊錄影工作階段轉專案不列第一版必要範圍；不得因此限制新專案的真實錄製與續錄。

## 3. 主流程與狀態

### 3.1 建立及錄製

建立時選專案名稱與位置，保留熟悉的螢幕、音訊、FPS、品質等錄製設定。開始前確認專案可寫、空間足夠、裝置與權限可用。新專案以首次錄製設定確定輸出畫布與 FPS。

錄製期間顯示精簡控制列、目前錄製長度、已完成片段數與收音狀態。編輯操作鎖定；目前寫入的片段不是可剪輯素材，不啟動預覽音訊。保留現有關閉防誤觸提醒。

### 3.2 暫停

按暫停後先顯示「正在保存片段」，安全結束檔案、確認可讀並記錄來源中繼資料；成功後才進入「已暫停」。失敗顯示原因並保留原檔，不假裝片段已可編輯。

暫停不強制搶走焦點或切換大型編輯畫面。控制列提供「編輯已錄內容」「繼續錄製」「結束本次錄製」。進入編輯後頂部固定顯示已暫停，以及繼續錄製入口。

### 3.3 繼續錄製與補錄

一般「繼續錄製」固定追加到時間軸尾端，與播放頭位置無關。

「在此補錄」是明確的另一項操作：

1. 在接點選擇插入；若在片段中間，預覽將分開的前後內容並確認。
2. 保存插入意圖，顯示補錄會放入的位置。
3. 停止預覽畫面及聲音、取消過期預覽工作，保存已完成編輯，再開始新錄影。
4. 補錄片段安全完成後才插入時間軸；中間位置的分割與插入視為一個可復原操作。
5. 開始失敗或沒有有效新片段時，原時間軸不分割、不留下空白片段；中斷但有內容則交由救援確認，不直接丟棄。

預覽停止或專案保存無法確認時，禁止續錄並說明原因，避免把播放聲音再錄進影片或丟失編輯。

暫停期間變更麥克風、系統聲音、游標設定只影響下一段，介面明示適用範圍。第一版不承諾變更已錄影像中的游標效果，也不新增系統／麥克風分軌錄製。

### 3.4 結束、關閉與重新開啟

「結束本次錄製」完成當前素材並回到編輯，不自動清除專案或強制輸出。「輸出 MP4」不會結束專案的可編輯性。

正常關閉：錄製中沿用先停止的保護；已暫停／編輯中等待保存完成。寫入失敗不能靜默關閉，提供重試或取消關閉。

重新開啟：恢復時間軸、片段設定、面板配置及最後確認的播放位置；提供繼續編輯、繼續錄製、輸出。當次復原／重做堆疊不承諾跨啟動保留；已保存的編輯結果必須保留。

續錄前重新偵測螢幕、音訊裝置、權限及磁碟；若舊螢幕或區域失效，要求重新選擇，不依失效編號錄錯螢幕。正常關閉的專案不標示為異常救援。

## 4. 編輯工作區

### 4.1 區域配置

| 區域 | 內容 | 互動約束 |
| --- | --- | --- |
| 頂部 | 返回主畫面、專案名、保存狀態、復原／重做、繼續錄製、輸出 | 正在錄製／已暫停／編輯中以文字加狀態標示 |
| 左側 | 按時間軸順序排列的片段清單：縮圖、名稱、長度、來源錄製時間 | 反映目前剪輯片段，不混用原始素材庫；可改名、排序、折疊群組 |
| 中央 | 大型等比例預覽、播放／暫停、前後一格、時間碼／總長 | 不能拉伸原始畫面；點片段不等於改變播放位置 |
| 右側 | 當前選取片段的時間、聲音、畫面屬性 | 無選取時顯示簡短提示，不露出無效控制；可收起 |
| 下方 | 刻度、主影片軌縮圖、附屬音訊波形、播放頭、範圍選取、縮放 | 高度可調；波形不是可隨意脫離影片的第二條編輯軌 |

1440×900 邏輯像素為主要設計稿尺寸：左右面板約 220／260，時間軸約 240 高，預覽取剩餘空間；實作可依可讀性調整，不能犧牲必要控制。

1280×720 預設收起右側屬性，改按需展開；視窗最小 1024×640 邏輯像素時左右面板可切換顯示，不能用重疊按鈕或微小字體塞滿。高 DPI 用邏輯尺寸，不硬套實體像素。

### 4.2 視覺與易用性

- 預設跟隨系統深／淺色；深色以中性炭灰為主，不用大面積純黑。主要文字至少 14 邏輯像素，輔助資訊至少 12。
- 藍色為選取／主要操作，紅色保留給錄製及刪除警告。選取同時有外框及文字，不只依賴顏色。
- 一般按鈕至少 32 高，常用主要動作至少 36 高；裁切邊緣保留至少 10 像素可命中的區域。
- 常用功能有文字標籤；罕用項收進選單。提供滑鼠提示、鍵盤焦點與中英文在地化，不把中文長字串裁成難懂的碎片。
- 時間軸預設能看清片段名稱、選取範圍及音訊波形；不讓大預覽擠掉整個編輯區。
- 選取片段以外框、清單及屬性同步；播放頭有獨立垂直線。播放到其他片段不擅自變更正在調整的屬性目標。

## 5. 時間軸規則

### 定位與播放

點時間刻度可跳轉，拖播放頭可 scrub。拖曳期間優先快速畫面且預設不發聲，放開後取得精準畫格。只發布最新定位結果，過期工作不可讓畫面倒退。

時間碼為主要操作單位，格數放在進階提示；逐格移動使用實際來源時間戳。播放／暫停按鈕在暫停時保留位置，再播放從該處接續。到片尾保持最後畫面，再按播放從頭開始。

提供符合整段、縮放滑桿、水平捲動；滾輪預設捲動，修飾鍵加滾輪縮放並在介面提示。時間碼與播放頭是同一定位狀態。

### 裁短、分割與刪除

- 拖片段左右邊緣裁短時間，顯示邊界預覽與新長度；可重新拉回未保留的來源內容，不修改來源檔。
- 播放頭上的分割建立兩個片段引用；零長度片段不允許產生。
- 使用明確的「選取範圍」工具拖出區間，支持輸入起迄時間；刪除預設移除區間並讓後段自動接上。不得把按片段拖曳誤判成刪除範圍。
- 區分「刪除片段」及「刪除選取範圍」。範圍跨多片段時操作一併生效、一次復原還原。
- 刪到全部空白後保留專案與原始素材；禁用輸出、允許復原和繼續錄製。
- 片段順序、裁短、分割、刪除、群組、屬性變更均可復原／重做；一次拖曳只建立一筆歷史。

### 排序、群組與合併

拖曳片段本體為移動，邊緣為裁短。重排顯示插入線並吸附接點，靠近邊緣可自動捲動；放開才提交，Esc 或移出有效區域取消。

第一版以單一片段或已建立群組為移動單位，不提供任意多軌對齊。左側清單和時間軸共用同一排序資料，不各自維護兩份順序。

連續錄製片段自動連續播放與輸出，使用者不必先執行檔案合併。「群組」只把相鄰片段作為整組移動，仍能展開或取消群組，不能重新編碼成不可拆的來源檔。

提供往前／往後及鍵盤操作替代拖曳；Space 播放／暫停、左右逐格、平台標準復原／重做、Delete 刪除、Esc 取消。編輯文字時不攔截這些按鍵；既有錄影快捷鍵需依目前模式清楚區分。

## 6. 片段屬性與範圍

第一版包括名稱、時間裁短、分割／刪除／排序、整段音量／靜音／簡單淡入淡出，以及畫面裁切／縮放／位置。這些是設定資料，來源素材不改寫。

畫面操作提供可視框線與一鍵還原；預設等比例「完整放入畫布」，不足處補底色，不自動拉伸或裁掉內容。不同尺寸續錄仍保留原始解析度，以專案畫布組合。

音訊跟影片一起移動。已混合的系統聲音與麥克風只提供整體音量，不顯示不可實現的獨立調整。淡入／淡出不超過片段範圍，音畫共用來源時間映射。

暫不包含變速、字幕、貼圖、花式轉場、獨立音訊多軌、游標事後重建。不得把參考圖片中的工具列全部照搬而承諾未規劃的功能。

## 7. 專案與保存

專案採可整體搬移的資料夾，含 `.opencam` 專案檔、sources、sessions、cache、exports。專案檔為具 schemaVersion、projectId、revision 的結構化資料；來源使用專案內相對路徑及穩定 ID，編輯片段使用獨立 ID 引用來源。

每個片段保存來源入／出時間（半開區間）、畫面／音訊設定；群組另外保存成員 ID。保存實際時間基準／PTS 索引，不以 nominal FPS 乘秒數猜測 VFR 或掉格錄影的位置。

每次完成剪輯後自動保存；連續拖曳結束後合併保存，目標一秒內啟動。保存狀態區分「正在保存」「已保存」「保存失敗」，只有落盤成功才能顯示已保存。

使用同磁碟暫存檔、必要的 flush、原子替換與最近可讀備份；正常保存不能留下半份 JSON。錄製片段完成與專案加入之間需有可重播的保存紀錄，避免 crash 後有素材但專案漏列。

同一專案同時只允許一個寫入者；第二個視窗只讀或提示已開啟，不能互相覆蓋。新版 schema 在舊程式中不嘗試覆寫；升級前保留可回復備份。

來源清理、快取清理、成品刪除是不同動作。專案模式禁止既有 DeleteWorkingFileAfterSuccessfulRemux 清理仍被專案擁有的來源；從時間軸刪除不釋放來源，以保留復原能力。第一版不提供自動永久刪除未使用素材。

使用者搬移整個專案後可重新開啟。來源遺失時顯示位置與受影響片段，提供重新連結並核對媒體資訊；不能略過片段輸出看似成功的縮短成品。

## 8. 系統分工與錄影安全

- 錄影層：沿用擷取、音訊、編碼、MKV 安全寫入與 watchdog；只交付確認完成的素材。
- 專案協調層：管理一個專案包含多次錄製 session，串接暫停完成、續錄前置檢查及保存。
- 編輯模型：維護來源引用、時間映射、順序、群組、屬性與復原命令；不得直接呼叫平台擷取 API。
- 預覽層：讀取已完成來源，維護可取消的解碼／定位、縮圖與波形快取。媒體工作者失敗須可重啟，不讓錄影來源消失。
- 輸出層：使用固定專案 revision 的快照進行合成、驗證及發布，不修改錄影 session 的救援狀態。

預覽引擎不在此規格預先指定。不得直接把上次 LibVLC 試作視為選型結論；先以來源分段、PTS 精準定位、跨接點音畫、取消／停止、Windows／macOS、散布條款等門檻比較候選，再寫具體實作計畫。

專案檔及重新連結路徑視為不可信輸入：驗證 schema、數量／大小界限、有限數值、媒體區間及路徑；拒絕越出專案根目錄的隱含引用、路徑穿越及符號連結越界。任何外部來源需明確匯入，不能以專案內容任意讀寫系統檔。

媒體子程序使用參數清單而非 shell 拼字串，有取消、逾時、有限日誌與明確資源所有權。編輯 crash 後保留已落盤專案及原始 MKV；未完成片段沿用救援流程，不先刪除。

## 9. 預覽與效能

禁止每次裁短／排序都重新轉完整部影片。以來源解碼與時間軸映射為主，縮圖／波形分批建立；必要時使用可重建代理素材或局部快取，但不得在預覽顯示已刪除區間的內容。

介面先呈現清單與時間軸，不等待整部影片掃描完成。背景工作有優先序和取消機制，使用者目前定位優先於遠處縮圖。舊畫面在新結果成功前維持並清楚標示準備中；新結果與時間軸 revision 不符就丟棄。

初始快取上限 2 GiB，可調整／清理並受磁碟空間警戒約束；釋放最久未使用且非活動中的快取。不得因快取滿而刪除 sources 或必要專案保存資料。

驗收測資為至少兩小時、200 個片段的 1080p 專案，涵蓋 30／60 FPS、無聲、音訊來源變更、非零 PTS、掉格／可變間距時間戳。效能目標須在實際公開硬體／版本條件下量測：已索引本機素材 warm seek p95 ≤250ms；cold seek 與開啟耗時另外記錄，不能拿短合成片段結果冒充長片效能。

以上是驗收目標，不是已達成數據。若無法達成，報告瓶頸與替代設計，不能偷偷把產品限制縮成只能剪 20 秒。

## 10. MP4 輸出

「輸出 MP4」提供建議設定：專案畫布、FPS、H.264/AAC、高品質；預先顯示處理方式、目的地與空間需求估計，進度可取消。

未調整且媒體條件相容的完整片段可走 stream copy；精準邊界剪輯、畫面變形、音量處理或不相容素材走重新編碼。不可保證所有剪輯均無損；第一版不以複雜混合 smart-render 作必要前提。

對不同來源尺寸／FPS，輸出依專案設定做等比例合成與明確時間重採樣；音訊依同一時間映射處理，不因排序或補錄而累積漂移。

輸出先寫唯一暫存檔，驗證視訊／音訊、時間長度及可解碼性，成功後才發布成品。目的地不能是來源、專案檔或已存在的唯一成品；同名預設產生新名稱，不靜默覆蓋。

輸出期間第一版鎖定該專案的編輯與續錄，可取消輸出後返回；輸出不得變更快速錄影原有設定，第一版不承諾同時錄製與輸出。失敗／取消只清理本次輸出暫存，既有成品、來源和專案保留。

## 11. 設計與實作階段門檻

### A. 介面與流程確認

高擬真可操作模型需展示主程式雙入口、最近專案、錄製中、暫停保存中、編輯、補錄插入、重新開啟續錄、輸出進度及失敗狀態。需有真實感的螢幕錄影縮圖與波形，不再以 A/B/C/D 大字母當作產品介面驗收。

模型不得執行錄影或宣稱編碼完成。使用者先確認主要畫面及操作，再制定分階段實作計畫，寫程式前不反覆建立不可交付的原生示範 App。

### B. 專案與真實錄製閉環

從 OpenCam 入口建立專案，真實錄三段、正常關閉、重開、補錄第四段。核對素材不被既有清理政策刪除；模擬保存失敗、異常退出、磁碟不足及裝置失效。未通過不進入大量剪輯 UI 實作。

### C. 基本剪輯與成品閉環

真實錄影完成裁短、刪除中段、分割、排序、補錄插入、群組與復原／重做。核對預覽內容與 MP4 完全相同的片段順序和保留區間，跨片段音畫同步、輸出取消不丟資料。

### D. 屬性、效能及雙平台

完成音量／淡入淡出、畫面裁切／縮放與還原。Windows、macOS 各自執行實際 GUI、錄音、長影片、重啟及輸出驗收；加入 1280×720、高 DPI、中英文、深淺色的可用性檢查。

每階段先測試再實作，完成後保留來源雜湊、輸出探針、音畫標記、操作截圖及性能紀錄。缺平台或硬體就標示 BLOCKED，不能只靠另一平台或 mock 宣稱支援。

## 12. 端到端驗收故事

使用者建立「教學示範」專案，錄 A、暫停、錄 B、暫停、錄 C；進入編輯，刪除 B 中間口誤，把 C 移到 B 前，在 A 後補錄 D。保存關閉，隔天重新開啟，順序與裁切仍在，再錄 E。輸出得到 A / D / C / B（刪除口誤後）/ E，聲音與畫面一致。原始五次錄製均保留，再改順序可以輸出另一份 MP4。

此故事必須從同一 OpenCam 主程式入口完成；這才是功能完成標準。版本號、推送、合併及 Release 另行授權，此設計同意不包含發布授權。
