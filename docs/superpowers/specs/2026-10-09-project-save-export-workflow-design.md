# 專案儲存、輸出與編輯操作調整

日期：2026-10-09
狀態：使用者已確認書面規格；鉛筆按鈕依後續確認改為有明確按鈕外觀的純圖示。

## 目標與限制

保留「開始錄影 → 停止 → 取得 MP4」的簡單流程，同時讓需要分次錄製、剪輯的使用者能只保存專案，最後再輸出。明確區分已保存的原始錄製、尚未儲存的編輯、當機復原草稿。

- 暫緩剪輯預先處理／預先轉檔快取，不覆寫原始 MKV，也不為此複製影片。
- 本次不更改版本，不合併、不發布、不觸發 GitHub Actions。
- 已核准的快速輸出、預覽與資料夾修正維持獨立工作，不因本規格視為已完成。
- 正在錄影或正在啟動、停止、輸出時，不允許切換專案或進行剪輯；原有錄影資料保護不得削弱。

## 1. 停止錄影與 MP4 輸出

首頁目前專案資訊區提供「停止錄影後自動輸出 MP4」核取方塊，附說明「關閉時僅保存錄製，可稍後輸出」。新專案與缺少此設定的舊專案預設開啟，設定隨專案保存。這是錄影偏好，不計入影片內容是否改變的判斷。

- 開啟：停止後先可靠保存錄製，再執行 MP4 輸出。
- 關閉：停止後保存原始素材與專案，不產生 MP4；顯示「錄製已保存，尚未輸出 MP4」。
- 首頁與編輯器都保留手動輸出入口，錄影中禁止輸出。
- 輸出失敗不得使成功錄製的素材遺失；提供重試，不能顯示錄影遺失或完成輸出。
- 專案記錄最後成功輸出的內容指紋、輸出檔位置與完整性資訊。內容指紋包含素材識別、片段順序、裁切與影音效果及輸出設定，不含專案名稱、預覽設定或視窗狀態。
- 相同內容且既有輸出檔仍存在並通過完整性核對時，提供「開啟既有檔案／另行輸出／取消」。缺檔或檔案已更動則重新輸出。不得默默覆寫既有檔案。

## 2. 正式儲存與復原草稿

目前 `ProjectRecordingCoordinator.ApplyEditAsync` 與編輯歷史操作立即呼叫 `FlushEditsAsync`，關閉流程也會自動保存；因此現行「儲存專案」不能代表明確的提交時點。改為下列分工：

| 資料 | 保存時機 | 是否可因放棄編輯而刪除 |
| --- | --- | --- |
| 完整錄製片段、素材清單與錄製工作階段 | 片段完成立即可靠保存 | 否 |
| 裁切、排序、名稱、音量與畫面效果 | 按「儲存專案」才寫入正式編輯狀態 | 可回復到正式保存狀態 |
| 尚未儲存的編輯草稿 | 背景延遲合併寫入 | 使用者明確放棄後可移除草稿 |

### 正常操作

- 編輯、復原、重做只修改工作中狀態並標記「尚未儲存」。
- 「儲存專案」先驗證屬性欄尚未套用的輸入，再原子保存正式狀態；只有成功後才顯示「專案已儲存」。驗證或寫入失敗保留工作中資料與錯誤訊息。
- 關閉專案／程式或切換專案，有未儲存修改時詢問「儲存／不儲存／取消」。僅返回首頁不卸載專案、不丟棄修改。
- 開始續錄或輸出前，如仍有未儲存編輯，同樣解決儲存選擇；不默默替使用者儲存。選擇不儲存則使用正式保存的編輯狀態；取消不開始作業。
- 已錄製素材的耐久提交與編輯草稿分開管理。任何捨棄草稿、還原或重做，都不能刪掉新錄製的原始檔。
- 尚未開啟專案時不顯示「已儲存」，改為明確空白狀態提示。

### 當機復原

- 復原草稿只含編輯中繼資料，不含影音複本；保留一份草稿與一份備份，套用既有 JSON 大小、深度與路徑安全限制，避免無限增長。
- 草稿綁定專案 ID 與正式保存的基準修訂；背景寫入序列化，原子替換，不能把較舊非同步結果覆蓋較新草稿。
- 再開啟時若發現相符基準的未儲存草稿，詢問「復原未儲存修改／捨棄草稿」。復原後仍標示尚未儲存。
- 基準不符或草稿損壞不得自動覆蓋正式專案；保留可診斷資訊並明確告知，開啟正式保存版本。
- 正式存檔包含可識別已提交草稿的標記，解決正式存檔成功、草稿清理前當機而導致舊修改再次被復原的問題。
- 不儲存時先可靠記錄草稿已捨棄，再清理；清理失敗不能使下次啟動自動復原已放棄的修改。
- 草稿寫入失敗顯示「自動復原保存失敗」，不得冒充正式已儲存；手動保存仍可重試。

## 3. 左側片段清單拖曳排序

- 縮圖模式與精簡模式皆可拖曳；超過拖曳門檻才開始移動，單擊仍是選取。
- 顯示插入線與被拖曳項目的視覺回饋；靠近清單上下邊緣時自動捲動，可移到最前或最後。
- 已群組片段作為整組移動，不允許插入另一群組內部破壞群組。
- 放開後呼叫與時間軸相同的排序命令，更新兩處順序並保留選取；一次拖曳只產生一步復原。原位置放開不產生修改。
- Esc、放到無效區域或離開拖曳目標可取消；錄影／輸出／其他不允許編輯狀態禁止拖曳。
- 未套用的屬性輸入維持既有保護，不因拖曳暗中套用或丟失。
- 保留既有非拖曳排序方式供精確操作與鍵盤使用。

## 4. 編輯器標題與圖示

- 編輯視窗繁體中文標題統一為「編輯錄製內容」，英文為「Edit Recording」。不任意改名其他仍代表專案檔案的文字。
- 首頁「編輯錄製內容」改用簡潔的「影片框＋編輯筆」向量線條圖示，沿用其他工具按鈕的線寬、大小、垂直對齊與狀態色，不使用 emoji。
- 專案名稱後方緊接鉛筆圖示按鈕，不顯示文字；以淡色底、細邊框、滑鼠移入及鍵盤焦點效果辨識可點擊。提示與無障礙名稱為「更改專案名稱」／「Rename project」，不放在整列最右端。
- 長名稱以省略號顯示且可查看完整名稱；保留更改名稱按鈕可見，窄視窗不能與右側儲存／輸出重疊。
- 儲存狀態集中顯示在名稱下方，以「尚未儲存／專案已儲存／儲存失敗」區分；移除其他突兀且重複的已儲存文字。

## 5. 元件責任與相容性

- Coordinator 與 project store：正式修訂、草稿復原、錄製提交與鎖定；不讓 UI 直接操作素材檔。
- 編輯歷史：工作中狀態、儲存基準與復原重做；正式保存後仍保留本次開啟期間合理的復原歷史，dirty 依與保存基準的差異計算。
- Controller／ViewModel：儲存選擇、停止輸出策略、命令可用性與狀態文字。
- 左側清單與時間軸：共用排序命令，避免維護兩份順序。
- 儲存格式加入必要欄位並明確處理舊檔預設值；若需要提高 schema，使用經測試的遷移，舊程式不得把未知狀態靜默覆寫。
- 本次沒有修改來源 MKV 功能，也沒有剪輯預渲染磁碟快取。

## 6. 驗收條件

1. 自動輸出開／關兩條流程、重新開啟後偏好保持、舊專案預設值、輸出失敗錄製仍可用。
2. 同內容重複輸出提示、僅改名稱不誤判內容改變、輸出檔遭替換或移除能正確重新輸出。
3. 剪輯後正式檔未被改寫，存檔後才更新；儲存／不儲存／取消及返回首頁行為符合規格。
4. 續錄後放棄剪輯不丟素材；當機、磁碟滿、草稿損毀、基準衝突與原子存檔中斷測試。
5. 兩種清單模式排序、首尾位置、群組、取消、捲動、一次復原與時間軸一致。
6. 中英文、長名稱、窄視窗與高 DPI 的圖示、名稱按鈕、標題與狀態配置檢查。
7. 執行相關自動化測試；Windows 原生拖曳／影音實機未驗證時如實註明，不以 macOS 或單元測試代替。
