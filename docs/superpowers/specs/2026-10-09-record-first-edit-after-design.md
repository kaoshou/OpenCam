# 直接錄影、隨後編輯：流程修訂

日期：2026-10-09（Asia/Taipei）

狀態：使用者已同意操作方向與停止後自動產生 MP4；本書面修訂待審閱，尚未實作。

本文件修訂 `2026-10-08-recording-project-editor-design.md` 的入口、錄製生命週期及預設輸出政策。原先三欄編輯畫面、非破壞性剪輯、復原／重做、來源保護及獨立輸出等要求仍有效。先前「快速錄影與手動新建專案分流」不再作為使用者必經流程。

## 1. 已確認的使用體驗

- 首頁移除上方「錄影專案」按鈕與說明整排。
- 主控制列順序為「開始錄影」「暫停／繼續」「停止錄影」「內容編輯」「修復救援」，設定仍在右側。
- 使用者直接按開始錄影，不先輸入專案名、不選專案檔、不經新建精靈。
- 暫停且片段已安全保存，或錄製完成且素材可讀時，可以進入內容編輯。
- 停止後照常自動產生 MP4，同時保留原始素材與可續編資料。是否進入編輯由使用者決定，不強制切換視窗。
- 下次仍能從內容編輯入口找到先前錄製內容，繼續編輯或續錄，不必先輸出影片。
- 僅本機開發及驗證；不推送、不合併、不改版本、不發布。

## 2. 架構選擇

採用「錄影開始時自動建立受管理的錄影資料」：沿用現有專案儲存層與 Recorder 單一寫入者，將專案建立變為後台交易。介面用「錄製內容」稱呼，不要求使用者理解內部專案格式。

比較：

1. **開始時自動建立（採用）**：從第一段起即保留來源、暫停剪輯與中斷救援資訊，不需要搬移正在使用的素材。
2. 停止後才把快速錄影轉成專案：難以支援暫停時編輯，且可能已按舊設定刪除來源。
3. 只把 MP4 當素材：失去原始分段與編輯記錄，不能满足原始片段續編需求。

不直接把既有 `session.json` 當作永久編輯格式，也不讓 UI 成為第二個專案寫入者。

## 3. 自動保存與命名

選用目前錄影儲存位置，內部建立 `OpenCam Recordings/<日期時間>-<唯一識別>/`，包含 `.opencam`、sources、sessions、cache、exports 等既有結構。以時間產生顯示名稱，使用者可稍後改名；資料夾唯一識別防止同秒錄影撞名，不依使用者輸入名稱拼接任意路徑。

開始前先確認目錄、鎖定、可寫及保存成功，再啟動擷取。失敗時明示原因，不偷偷改用無法續編的錄影模式。第一次有效素材初始化畫布／FPS，沿用原始解析度保存。

未產生有效素材的啟動失敗，不加入正常最近內容列表；若已有不確定或部分素材，保留並交由既有救援流程確認，不自動刪除。

已保存的編輯結果可跨次開啟；復原／重做維持當次使用期間，不承諾跨啟動復原堆疊。

## 4. 按鈕與狀態規則

| 狀態 | 內容編輯行為 |
| --- | --- |
| 閒置，沒有本次錄製 | 開啟最近錄製內容／開啟既有錄製內容；沒有內容時提示先開始錄影，不提供必經的新建專案 |
| 準備或正在錄影 | 停用，提示先暫停或停止 |
| 正在保存片段／保存失敗／狀態未確認 | 停用，先完成保存或明確恢復狀態 |
| 已暫停，有已確認素材 | 直接開啟本次內容，仍保持暫停；預览不會啟動錄音 |
| 停止並保存完成，MP4 處理中 | 顯示 MP4 進度；為避免首版競態，完成或失敗前不接受編輯變更或下一次擷取 |
| MP4 完成，或 MP4 失敗但來源已確認保存 | 可編輯本次內容；MP4 失敗不等於素材遺失 |

主視窗與編輯視窗共用同一錄影／專案狀態，不以「編輯視窗是否開啟」取代錄製狀態。返回主視窗不另開第二個 Recorder，不錯誤解除錄影控制鎖定。

編輯器內保留已確認的版面，頂部提供返回、內容名稱、保存狀態、復原／重做、繼續錄製、在此補錄及輸出 MP4。移除必須新建專案才能錄製的流程。新的獨立錄影從首頁「開始錄影」啟動；編輯器「繼續錄製」才明確延續目前內容。

## 5. 自動 MP4 與編輯後輸出

每次明確停止錄影，先完成素材提交與保存，再取得固定 revision 的時間軸快照並自動輸出 MP4。無剪輯且參數相容時保留原有快速 Remux 能力；若暫停期間已裁剪／排序或調整屬性，輸出的必須是已保存的編輯結果，不能仍輸出被刪片段。需要精剪時使用已驗證的重編碼路徑。

從舊內容續錄後停止，自動輸出該內容當下完整時間軸的新成品。輸出至目前選定儲存位置，以唯一檔名避免覆蓋前次成品。介面清楚指出本次產生的檔案。

停止後再編輯時，只保存編輯，不每次操作就重編碼；使用者按「輸出 MP4」才產生另一份新成品。自動輸出與手動輸出共用同一來源映射、屬性處理與驗證規則。

輸出成功需驗證影音與完成狀態，才發布最終檔名；取消、磁碟不足或失敗只清理由本次輸出擁有的暫存檔，不能刪除原始素材、編輯資料或既有 MP4。提供重試，重試不能重複加入錄影片段。

## 6. 來源保留、舊設定與救援

新版錄製內容的 sources 是永久可編輯素材，不是可在 MP4 成功後刪除的工作檔。舊的 `DeleteWorkingFileAfterSuccessfulRemux` 設定不得刪除此類來源。

保留原設定值供舊工作階段相容處理，但在新版錄製設定中不再呈現會誤導使用者的可用來源刪除選項；改以清楚說明告知「保留原始素材供後續編輯，會增加儲存空間」。不默默改寫使用者既有偏好，也不在背景清除錄影素材。快取可按配額清理，但不能把 sources 當快取。

最近內容只在有效保存後加入，儲存失敗、失效路徑與缺少來源要明確提示，不退回讀取未驗證任意路徑。正常關閉內容不是異常救援；既有舊錄影救援仍可用。舊 MP4 任意匯入及批次刪除素材管理不在此次入口修訂範圍。

## 7. 續錄與聲音隔離

暫停後編輯，按繼續時先停止預覽畫面、解碼工作與聲音，等待停止確認並保存，再啟動下一段。無法確認停止或保存失敗則不啟動擷取。

一般續錄追加尾端；「在此補錄」仍是獨立明確操作，新素材確認有效後才一次分割並插入，失敗不改原時間軸，成功可一次復原。

不改動 Windows/macOS 既有擷取策略、音訊裝置選擇及游標效果。錄製中關閉的保護繼續有效，不因新入口而中断錄影。

## 8. 驗收與施工順序

先完成自動錄製內容生命週期、雙視窗狀態與自動 MP4 契約，再接 UI 入口；不能先把按鈕搬過去卻仍打開空專案精靈。真正播放器、時間軸、補錄及精準輸出繼續依原規格完成，不把現有探針當已整合產品。

必測：

1. 全新啟動 → 直接錄影 → 暫停 → 內容編輯，不曾出現新建專案必要步驟。
2. 多次暫停／續錄 → 停止 → 自動 MP4，未進編輯者仍能正常取得成品。
3. 暫停剪除中段／重排 → 停止，MP4 必須反映剪輯，原始來源 hash 不變。
4. 停止後編輯 → 只保存不輸出 → 關閉重開 → 續錄 → 停止產生新成品，舊 MP4 不被覆蓋。
5. 開始失败、保存失败、Remux／精剪失败、取消、低磁碟及 IPC 回覆丟失，不刪来源、不重複提交、不錯報成功。
6. 舊來源刪除設定為 true，仍保留新錄製內容來源；舊救援相容。
7. 中英文、小視窗、長名稱、深淺色；「內容編輯」不擠掉停止或設定按鈕。
8. 原錄影設定、權限、關閉保護與音訊回歸；Windows 實機在僅本機 Mac 的限制下明確記錄未驗證。

完成定義仍包含真正原生 App 的錄影→編輯→保存→重開→續錄→MP4 故事。既有 546 PASS／13 SKIP 不代表本修訂已實作或驗收通過。

## 自我檢查

- 保留停止自動 MP4，並區分停止後編輯僅保存與使用者主動再次輸出，無相互矛盾。
- 不要求手動建專案，但仍保留單寫者、安全來源、可續編持久化；不是刪除底層格式。
- 明確處理舊刪除設定、沒有有效片段、輸出失败、重試及跨視窗鎖定。
- 不擴充字幕、多軌、舊 MP4 匯入或發布；Windows 未驗證不宣稱通過。
