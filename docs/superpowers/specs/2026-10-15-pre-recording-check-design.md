# OpenCam 錄影前檢查與試錄設計

## 目的與範圍

使用者希望在正式錄製前，確認麥克風、系統聲音與錄影範圍，降低選錯來源或錄完才發現無聲的風險。本次提供檢查視窗與可選的5秒試錄／回放，不加入自動語音辨識、雲端服務、強制測試音或永久背景監聽。

這是跨 UI、Recorder 與原生擷取生命週期的架構調整，不只是提示文字。現有 `RecordingOrchestrator.GetAudioLevels` 依賴錄影 session／engine，`AudioLevelState.Resolve` 在非 Recording 狀態不提供有效讀值。不得把無資料當成零音量或檢查通過，也不修改正式錄影的健康判定以配合預檢。

## 使用流程

1. 從首頁開始新錄影或追加錄影時，先完成原有名稱／未保存確認，再顯示錄前檢查。尚不建立錄製片段、不修改既有專案。取消直接返回。
2. 視窗明示「正在預覽所選畫面及偵測已啟用的收音；按試錄才儲存測試影片」。顯示螢幕名稱、實際錄影區域與尺寸、範圍預覽，以及各自獨立的麥克風／系統聲音卡片。
3. 麥克風提示「請說幾句話」，系統聲音提示「請播放一段有聲內容」。顯示目前裝置、即時音量與最新狀態；不播放強制提示音、不把麥克風訊號當成系統訊號。
4. 使用者可以返回調整裝置或範圍、選擇「試錄5秒」，或按「開始正式錄影」。無訊號時須明確確認繼續；硬性錯誤必須排除，或由使用者明確停用對應音源並重新檢查。
5. 正式開始前，停止並等待預覽、偵測、試錄及回放完全退出，再用同一份確認過的設定走原有正式開始流程。不能讓測試擷取與正式錄影同時占用來源。

檢查每次開始／追加錄影都顯示，不增加永久略過開關。暫停後恢復時，若來源、裝置、範圍或權限未變，不重複打斷；變更時重新檢查。這是風險降低機制，不保證未來錄影中裝置不會故障。

## 顯示與開始條件

| 狀態 | 顯示及處置 |
| --- | --- |
| 使用者未啟用音源 | 顯示「未啟用」，不要求該音源有聲；全部關閉時明確標示無聲錄影 |
| 正在等待／尚無有效樣本 | 顯示「等待訊號」，不能顯示綠色通過 |
| 有新鮮有效樣本且有音量 | 顯示「偵測到聲音」，不宣稱聲音內容或品質正確 |
| 有有效樣本但安靜 | 顯示「目前未偵測到聲音」，提示說話／播放內容；允許使用者確認後繼續 |
| 樣本過期、擷取失敗或裝置消失 | 顯示「無法確認收音」，與安靜區分；重試或明確關閉該音源，不以舊讀值通過 |
| 畫面權限不足、範圍無效或螢幕消失 | 禁止開始，提示修正與重新檢查 |

預覽有影像仍需使用者確認內容；黑色畫面可能是正常內容，不能只依像素黑色判定擷取失敗。檢查所用的螢幕識別、音源／裝置識別與範圍必須與正式設定一致；不支援的來源顯示原因，不悄悄改用其他來源。

## 試錄與回放

- 使用者按下試錄後，從第一個有效畫面及已啟用音源啟動完成時計5秒；啟動、停止與取消另有有界期限，不把設備初始化時間當成已錄內容。
- 使用正式錄影的擷取與編碼設定產生獨立測試 MKV，放在應用程式專用暫存子目錄。不得寫入正式專案、增加片段／章節、更新專案修訂、觸發正式自動輸出或列入正式救援清單。
- 結束並關閉寫入後，檢查檔案可讀、影片存在及預期音軌存在；有音軌不代表有實際聲音。提供畫面與混合聲音回放，由使用者確認；麥克風與系統音量仍以獨立來源資料判定，混合回放不能證明兩個來源各自正確。
- 回放時停止音源偵測，避免把試聽聲音當成系統收音成功，也避免麥克風回授。重試或重新偵測前停止回放。
- 允許提早停止／取消。關閉視窗或結束測試時只清理本次擁有的測試檔與程序；不刪除任何正式錄影、救援檔或使用者選取檔案。清理失敗記錄固定階段與原因，提示測試資料可能殘留，不隱藏錯誤。

## 架構選擇

僅檢查設定與權限最便宜，但不能驗證真的有收音；直接使用正式專案錄一段再刪除則容易污染專案與救援狀態。採用 Recorder 端獨立 `PreflightCoordinator`，與正式擷取互斥，重用平台擷取／engine factory、媒體探測及播放能力，但不借用正式 session、共享原生擷取實例或修改現有 orchestrator 狀態。

- Core：定義設定快照、檢查識別、來源狀態與結果。檢查結果只對該次設定與裝置有效；快照變更、裝置消失或權限變更立即失效。
- Recorder：管理 `Preparing → Checking → TrialRecording → Reviewing → Stopping → Closed` 的明確狀態與獨佔租約。提供開始／讀取／試錄／停止檢查命令，接在既有認證 IPC；以 operation ID 防止重複試錄與延遲回覆覆蓋新檢查。樣本及影格有大小與更新頻率上限。
- Windows／macOS：以新生命週期的來源取得實際、分開的音量與畫面，不以合成數值、裝置清單或單純建立物件宣告正常。平台不支援時回報受限；權限提示只在使用者開啟檢查的流程中發生。
- UI：呈現檢查結果與明確的取消／重試／試錄／開始動作，不直接操控原生擷取。不加入新第三方依賴、專案 schema 或持續背景服務。

正式錄影若正在執行、停止中、狀態不明或資源尚未釋放，拒絕開始預檢。預檢或試錄停止失敗時，不直接開啟第二套正式擷取；提供重試／取消及明確錯誤。取消、關窗、UI斷線和 Recorder 結束都必須停止並等待本次程序、原生來源及 handle 回收。日誌不記錄音訊樣本、影像內容或敏感原生參數。

## 驗證與交付界線

自動測試涵蓋：未啟用與等待／安靜／無法讀取的區分、獨立來源、不接受過期數據、設定失效、重複指令、開始互斥、5秒計時、取消與遲到回覆、試聽不回灌、暫存目錄限制、專案／救援零變更及清理失敗。

Windows與macOS實機確認：選錯／拔除麥克風、系統內容靜音、兩音源同開、各音源單開、無聲錄影、權限拒絕、螢幕變更、區域座標／DPI、回放後立即正式錄製，以及多次開關檢查後無殘留擷取程序。未執行的實機項目只能標待驗證，不能以 UI 或假資料測試代替。

本階段只確認設計，沒有啟動畫面或音訊擷取、沒有實作完成或驗收通過的主張；版本、推送與發布需另依使用者要求處理。
