# 錄製前音訊確認與獨立準備狀態區

狀態：畫面方向已獲使用者同意；本書面規格待確認，尚未實作。

## 目標與範圍

將錄製前檢查改為確認聲音：移除錄影範圍預覽，五秒試錄與回放都只處理音訊。正式錄影仍錄製原設定的畫面與音訊，不改編碼器、錄影範圍或專案格式。

保留清楚的準備與載入提示，不用黑色預覽區充當狀態區，也不以點擊按鈕當作已經開始錄製。這是後續功能變更，不修改已發布的 v0.3.10 或自動啟動下一次發布。

## 介面配置

視窗標題為「錄製前音訊確認」。移除畫面預覽、錄影範圍文字與預覽延遲說明，縮小視窗，保留系統音訊與麥克風兩張精簡音源卡片。

```text
錄製前音訊確認
確認要錄製的聲音；聲音測試不會錄製畫面。

麥克風                         系統音訊
裝置／啟用狀態                 裝置／啟用狀態
音量條與收音狀態               音量條與收音狀態

┌ 固定位置的狀態區 ─────────────────────┐
│ 活動指示／狀態文字                     │
│ 次要說明；試錄開始後才出現五秒進度      │
└──────────────────────────────────────┘

測試聲音 5 秒　播放／停止　重新檢查
                         取消　確認並開始錄製
```

狀態區放在音源卡片下方、操作按鈕上方。預留主要文字、次要說明及進度高度，避免狀態切換時按鈕跳動；長錯誤與英文可換行，不以過小固定高度截斷。平常採中性色，只有錯誤採明顯警示色；不保留大型空白預覽框。

啟用的音源顯示即時音量；未啟用的音源顯示「未啟用，不會錄製」，不顯示音量或收音引導。沒有新樣本不能假報即時音量，靜音也不等同裝置失敗。回放期間不將回放聲音標示為即時輸入。

## 狀態與雙語文字

所有文字透過既有語系資源提供，不在程式碼硬寫中文。

| 狀態 | 中文主文字 | 英文主文字 |
| --- | --- | --- |
| 初始化音訊 | 正在準備音訊裝置，請稍候… | Preparing audio devices… |
| 可以確認 | 請說話或播放聲音，確認音量。 | Speak or play audio to check the levels. |
| 試錄啟動 | 啟動聲音試錄中，請稍候… | Starting audio test… |
| 實際試錄 | 聲音試錄中…剩餘 {0} 秒 | Recording audio test… {0}s remaining |
| 試錄收尾 | 正在處理試錄音訊，請稍候… | Preparing test audio for playback… |
| 可回放 | 聲音試錄完成，可播放確認。 | Audio test ready. Play it back to check. |
| 正在回放 | 正在播放試錄音訊… | Playing test audio… |
| 正式啟動 | 正在準備錄製，請稍候… | Preparing to record… |
| 啟動結果未確認 | 正在確認錄製狀態，請稍候… | Confirming recording status… |
| 正在取消 | 正在停止並釋放裝置，請稍候… | Stopping and releasing devices… |

錯誤在同一狀態區提供可理解的訊息與適用的重試操作，不只顯示無限轉圈。準備期間採不定進度，不顯示虛構百分比或啟動倒數。五秒計時只從音訊引擎確實啟動後開始，且由後端時間狀態驅動。

## 操作流程

1. 開啟確認視窗即顯示音訊準備狀態；只初始化使用者選取的音源。
2. 準備完成顯示音量與引導，可直接確認開始，不強制試錄或勾選確認。
3. 按「測試聲音 5 秒」立即顯示啟動中；收到實際啟動確認後才顯示試錄中與五秒進度。
4. 五秒後顯示處理中，待寫入、關閉及音訊驗證完成才允許回放。回放不開啟影像解碼器。
5. 確認開始時，先停止試錄／回放與檢查音源，確認釋放成功；同一狀態區接續顯示正式錄製準備中。
6. 正式錄影確實啟動後才關閉準備視窗。若 IPC 逾時但結果未明，保持鎖定並確認狀態，不誤報失敗、不允許重複啟動。
7. 初始化與試錄期間允許安全取消，停止工作並清理暫存資料。正式啟動命令送出後，不以關閉視窗或取消本機等待冒充取消錄影；必須等後端明確確認。未確認期間保留狀態視窗及既有安全處理。

沒有選取任何音源時，直接略過音訊確認與試錄，但仍顯示精簡的「正在準備錄製」狀態視窗；不先啟動音訊裝置。原設定關閉錄製前檢查時也略過音訊確認，但仍保留正式啟動狀態提示。開始、續錄與插入錄製都使用一致的準備規則，保留各自既有專案與輸出保護。

## 技術邊界與選擇

採真正的音訊專用檢查／試錄路徑，不採「隱藏預覽但繼續擷取影片」。目前 `PreflightTrialSession` 仍依賴影格就緒、影片探測、合成影片專案與影像回放，必須移除這些音訊檢查路徑上的依賴，而非只修改 XAML。

- 音訊檢查使用獨立生命週期的音源，不借用正式 Recorder 的單例擷取資源。
- 平台音源的裝置身分、選取來源、混音與音量行為應與正式錄影一致；音訊測試不擷取螢幕、不啟動影片編碼或解碼、不輪詢 RGBA 影格。
- 音訊專用介面／實作與正式 `IScreenRecorderEngine` 分離，避免改變正式影片輸出的既有契約。具體類別與封裝格式在實作計畫中定案；必須支援所選來源的實際收音與可驗證回放。
- 試錄沿用隔離暫存目錄與受控輸出持有權；完成後檢查音訊串流、可解碼性與合理時長，而非要求影片影格、畫布或影片編碼器。
- 保留 operation ID、server instance、configuration revision、lease、確認與停止協定的安全條件；音訊就緒條件取代影格就緒，不降低錄影前必要權限、輸出或專案驗證。
- 音訊檢查成功只代表音訊確認，不宣稱已驗證螢幕擷取或正式影片編碼器；正式開始仍執行既有驗證。
- 新鮮音量取自當前檢查／試錄實例；停止前禁止後續讀取已釋放音源。回放、重試、取消與視窗關閉均清理工作與暫存音訊。
- UI 的正式準備顯示需整合現有 `RecordingStartCoordinator`；不得將 `StatusUnconfirmed` 視為啟動成功或已停止。

## 驗收與回歸

- 麥克風、系統聲音、兩者、皆無四種選項；未勾選來源不初始化、不顯示假音量、不混入試錄。
- 用可控啟動確認測試：延遲啟動期間只顯示啟動中，五秒計時尚未開始；收尾未完成不得回放。
- 音訊檢查／試錄沒有螢幕擷取、影片編解碼、影格 IPC 或正式專案寫入。
- 音量新鮮度、靜音、缺樣本、裝置遺失及停止後不再讀取。
- 試錄含有效音訊且無影片串流；回放、停止、重試與取消不遺留資源或暫存檔。
- 正式啟動慢、失敗、IPC 逾時、狀態未確認、重複點擊及關閉視窗，不造成背景錄製而 UI 誤認停止。
- 無音源與設定略過確認時，準備狀態仍顯示；正式錄影、續錄、插入錄製不退化。
- 中英文全部狀態、文字換行、按鈕可達性與緊湊版面。
- Windows／macOS 實機確認裝置、系統聲音與混音；合成與無頭測試不能冒稱已完成實機驗收。
