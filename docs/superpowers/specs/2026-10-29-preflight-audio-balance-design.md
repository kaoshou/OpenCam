# 錄影前音訊平衡設計

## 已確認的範圍

在錄影前音訊確認提供系統聲音、麥克風各自的 0～100% 音量、調整後的即時音量表，以及五秒試錄後的混音播放。兩個來源初始均為 100%。確認開始才記住設定，取消不保存。正式錄影必須使用同一組值。

不加入分軌、即時耳返、超過 100% 的增益、自動壓低背景音或自動正規化。不修改作業系統音量、不改動既有影片、不更換 OBS/libobs 錄影核心、不升版、不發布。

## 方案與選擇

- 採用既有五秒試錄／回放擴充：已獲使用者同意；避免預設耳返的回授與延遲問題。
- 不採即時監聽輸出：需要額外回授保護，也容易讓試聽再次進入系統收音。
- 不藉此導入分軌：屬另一項錄製與剪輯功能，後續另行設計。

## 現況與架構

`PreflightAudioSession` 已擁有擷取、五秒試錄、封存驗證、回放與清理；`RecordingPreflightWindow` 顯示兩來源狀態。預檢透過 FFmpeg 音訊流程，正式錄影使用 `ObsCaptureRequest` 與原生 libobs；兩者必須明確套用相同的線性倍率及混音規則，不能只將現有音量表乘比例，卻漏掉實際音訊。

設定以整數百分比儲存，100 對應倍率 1，0 對應靜音；缺值相容舊設定為 100，超界值限制至 0～100。來源選取與錄音音量獨立：設成 0 不等於解除勾選，不得跳過裝置初始化或健康檢查。設定快照、預檢確認指紋與暫停續錄均須攜帶此值。

## 操作

- 沿用兩張音源卡，各有來源名稱、音量表、滑桿、百分比及狀態；未選來源的滑桿停用。
- 100% 為原音量，降低任一來源會降低其收錄音量；不改變使用者聽到的其他應用音量。
- 提供「恢復預設」，只重設兩個滑桿，不更換音源裝置。
- 新增混音總量表，必須來自真正混合後音訊，不可把兩個來源的 RMS／peak 相加冒充實測。
- 檢查中滑桿立即更新預估的來源衰減顯示；混音表若尚未套用最新值，須顯示更新中，不可顯示舊值作為最新實測。
- 變更後停止舊回放、使舊試錄失效，顯示「音量設定已變更，請重新試錄」。試錄及封存期間禁止修改，避免五秒內設定不一致。
- 回放沿用停止擷取後播放的生命週期；不將播放試錄的聲音再次收進試錄。
- 調為 0 顯示「錄音音量為 0」，來源健康狀態與輸出音量分開；正常靜音、音量過低、裝置故障不得混為一談。
- 音量提醒不宣稱自動修復削波，也不偷偷正規化；多來源總和需保留實際加總語意。

## 保存與正式錄影

視窗使用工作副本。成功完成使用者的確認交接後，將兩個值更新到主畫面設定並經既有設定儲存流程保存；錄影啟動失敗不回滾使用者已確認的偏好。取消、關窗、IPC 失敗不得保存未確認值。無音源或跳過預檢仍沿用已保存倍率。

原生 helper 對已選來源使用 libobs 來源音量，不改輸出視訊、時間戳、MKV 封裝或已存在的來源健康判斷。協定需處理舊 helper 不支援新音量的情況；不允許默默忽略非 100% 設定。

## 驗收

自動測試包含倍率預設／邊界／JSON 往返、配置及續錄傳遞、取消不保存、舊試錄失效、指紋過期、快速拖曳與關窗清理、兩 OS 預檢參數、OBS 請求、已知雙音訊的相對振幅與混音、0 音量健康來源、試聽不重收音、既有素材不變。

Windows 與 macOS 實機各驗證單來源、雙來源、正常靜音、零音量、試錄取消重試、暫停續錄、五分鐘音畫同步、MKV 與匯出 MP4、主觀回放。自動合成音訊測試不得代替實體裝置測試，未執行項目明確標記待人工驗證。
