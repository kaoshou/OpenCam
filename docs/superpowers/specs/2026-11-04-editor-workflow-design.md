# 剪輯器操作改善設計

日期：2026-11-04。基準：本機開發提交 `3df676f`，不是已發布 v1.2.1 的二進位檔。

## 目的與授權

使用者已批准五個改善方向：預覽排程、精確時間軸操作、快捷鍵、音訊編輯體驗，以及範圍預覽和儲存／輸出狀態。此文件經獨立 builder check，沒有重要未決問題；使用者於 2026-11-04 回覆「好」，確認採用此具體設計，之後批准依建議計畫在獨立工作目錄由同一實作者逐階段完成、最後獨立審查。實作與驗證結果見 `docs/testing/editor-workflow-validation-20261104.md`。

錄影可靠性、資料安全和現有操作優先。不修改 OBS/libobs 錄影核心，不引入舊核心或錄影 fallback；不修改版本號、公開 Release 或安裝套件。預覽與輸出繼續使用既有 FFmpeg 路徑。保留原始素材、草稿、復原和輸出驗證機制。

## 現況

- `ProjectWorkspaceView.axaml.cs` 使用 33ms 預覽輪詢及 1 秒背景工作輪詢；現有 bitmap 重用及播放／拖曳期間背景退讓已在上一項工作完成，不重複算新增功能。
- `ProjectWorkspacePreview.cs` 已限制同時一個靜態畫面請求，並檢查專案、修訂、server instance、播放意圖、畫質和 epoch。拖曳時保留畫面，但仍使用所選預覽畫質；拖曳結束未直接要求最後一張靜態畫面。
- `ProjectTimelineControl.cs` 有縮放、平移、選取、移動片段和書籤點擊；沒有逐格控制、可選吸附或滑鼠邊緣修剪手把。`ProjectWorkspaceTimeline.cs` 已有範圍起訖、刪除範圍與 TrimEdge 編輯命令。
- `ProjectWorkspaceView.axaml.cs` 有儲存／復原／重做快捷鍵，文字框保留原生文字復原。還須盤點所有輸入控制、彈出選單及全螢幕路徑，不能僅以 TextBox 類型判斷焦點。
- `ProjectWorkspaceProperties.cs` 已有音量、靜音、淡入淡出，修改自動套用。預覽解碼以實際音訊裝置時鐘同步，並經同一 render plan 套用效果；保留這條同步關係。
- 儲存、草稿、輸出狀態及失敗保全已有基礎，需改善呈現與釘住回歸，不另造一套專案狀態。

## Approaches

1. **逐步擴充現有元件（建議）**：共用時間換算、局部命令與狀態呈現；每階段均有可回歸成果，保持既有同步、來源驗證與取消機制。代價是改善分批交付。
2. 重寫剪輯器／預覽引擎：可統一互動，但會擴大同步與安全回歸面，不符合本次低風險改善目標。
3. 預設平行解碼／全面生成代理檔：可能降低部分延遲，但增加 CPU、記憶體、磁碟、失效管理和取消清理成本；不作為本次預設策略。

以下細節是實作者建議，非使用者已指定的精確數值或按鍵。先採方案 1，設計確認後再撰寫各階段 TDD 實作計畫。

## 階段 A：預覽排程與量測

- 選取片段、完成拖曳和手動定位，立即喚醒單一預覽排程器，不等待下一個固定輪詢；保留計時器作播放更新和補救，不新增並行靜態解碼。
- 排程合併連續定位，只保留最新待處理位置。已經執行的請求不得無界累積；專案切換、關閉、畫質改變須可取消或安全丟棄過期結果。
- 拖曳中採較低預覽畫質；放開後恢復使用者原畫質並強制刷新同位置，不能因 ticks 相同而命中低畫質快取。拖曳前若在播放，仍依現有播放意圖恢復，不因過期停止回覆意外重播。
- 保留最後有效畫面並顯示載入狀態；不能把不同專案或不再屬於保留區間的舊畫面呈現成新內容。
- 量測首次預覽、定位、跨片段播放、請求數、峰值解碼程序與記憶體；IPC 往返時間、媒體解碼時間及畫面實際顯示延遲分開。未量測前不承諾速度倍率。
- 先量測跨片段停頓及重複來源驗證成本，不移除雜湊／來源完整性檢查。只有證據支持且能保留驗證與取消上限，才另評估下一片段準備；不把這項探索當成已完成的加速。

## 階段 B：精確時間軸

- 以前／後一格按鈕及快捷鍵移動；使用專案 canvas 的有理數 FPS 換算輸出格，不用來源名義 FPS，不累加四捨五入後的 tick 步長。混合 FPS 影片仍以輸出時間軸為準。
- 播放中逐格先停止預覽，待停止確認再定位；頭尾夾限，結尾定位最後一個有效輸出格，不越界取片。
- 加入可關閉的吸附，預設開啟；定位與修剪吸附到片段邊界和有效書籤。門檻為畫面 8 DIP，依時間軸縮放換算；同距離時採較早時間，Alt 拖曳暫時略過吸附。
- 起訖標記與選取區間有明確對比，顯示開始、結束、長度；移動／修剪顯示目標時間和變更量。
- 修剪手把先顯示提案，放開才送一筆既有 TrimEdge 編輯，Esc 或遺失 pointer capture 取消；提交前核對專案、修訂及片段身分，保留最短有效內容和 undo。
- 不將波形峰值當作自動剪輯點，不在拖曳每一格寫入專案。

## 階段 C：快捷鍵與可發現性

- 剪輯器快捷鍵只在編輯視窗作用，不註冊新全域熱鍵、不改錄影與標註快捷鍵。
- 建議預設：Space 播放／暫停；Left／Right 前後一格；Shift+Left／Right 前後一秒；I／O 標記範圍起訖。保留現有 Cmd/Ctrl+S、復原及重做；避免預設無修飾的刪除範圍快捷鍵。
- 按鈕 hover、可及性名稱和鍵盤操作說明均顯示實際綁定。以共用命令解析器統一按鈕及按鍵行為，不在多個視窗重複維護按鍵表。
- 文字、數字、滑桿、選單、彈出視窗與 IME 組字期間保留控制項原操作；不得輸入片段名稱時觸發播放、修剪或標記。Space 在聚焦按鈕時不得同時觸發按鈕與播放。
- 本次不新增完整剪輯器按鍵自訂介面，先讓既有支援的設定與顯示一致；如果盤點發現並無剪輯器可設定按鍵，不以標註／錄影的設定冒充。新增按鍵自訂可獨立擴充，避免無意擴大設定格式。

## 階段 D：音訊試聽與可見狀態

- 增加選取範圍預覽與循環試聽；無完整有效範圍時停用。結尾為 exclusive，必須由預覽端界定音訊／畫面範圍，不能只靠 UI 計時停止而播出選取範圍以外內容。
- 到範圍尾端時先確認本次播放停止，再循環；不可同時存在兩個音訊輸出。切換專案、修訂、範圍、停止、關窗或取消循環，均使舊循環意圖失效。
- 顯示**預覽混音音量表**，以既有 render plan 效果後、預覽 mute gate 前的 PCM 實際取樣計算峰值與 RMS；只傳數值，不經 IPC 傳原始 PCM。預覽靜音狀態另外標示。這不是作業系統實際喇叭音量，也不是匯出時的全片離線響度分析。
- meter 綁定播放 generation，10Hz 上限、固定大小資料；停止／無取樣／故障時分別呈現待命／無資料，不顯示過期綠條冒充正常。非有限值拒絕或安全夾限，過峰值有文字提示。
- 片段清單或屬性摘要明示靜音、音量百分比、淡入／淡出；不重建整個屬性面板，不中斷文字輸入。
- 不加入麥克風／系統音訊分離：已混合素材仍只能調整整體音量；不新增錄音音軌格式或虛構來源獨立控制。

## 階段 E：儲存、輸出與錯誤恢復

- 分開顯示專案儲存狀態與最近一次輸出狀態；「已儲存」不等於「已輸出」。只把與目前專案／修訂相符的成功輸出標示為最新，舊輸出不暗示已包含新修改。
- 預覽範圍、播放中、等待儲存和輸出中使用不同提示，避免正常定位被說成儲存失敗。錯誤原因不得被後續輪詢的普通狀態掩蓋。
- 輸出取消或失敗保留選取片段、範圍、播放位置和未提交草稿；不得靜默 discard 或刪除原始媒體。媒體編輯成功造成時間軸改變時仍按既有規則重新校驗範圍，不保留已無效座標。
- 繁體中文、英文、日文同步；沿用既有視覺語言，不把全部新控制塞進一列。保留小視窗和全螢幕操作。

## 驗收與交付

每階段先新增有意義的失敗測試，再最小實作、相關回歸和建置；全部階段完成後整套測試、網站文字測試、版本一致性檢查及獨立程式碼審查。原有 Linux/GNOME 未提交變更原封保留。

重點回歸：快速定位過期回覆、畫質切換同位置、播放／拖曳交錯、關窗釋放、300 片段快取上限、20/30/30000÷1001 FPS 邊界、多源 FPS、修剪取消／復原、IME與數值輸入焦點、範圍尾端音訊不外漏、循環取消、meter generation、靜音／無聲／無音軌／損壞素材、儲存及輸出失敗保全。

實際播放須用有時間碼及可對照聲音的素材，量測跨片段和範圍重播；Windows、macOS、Linux 本機可執行測試與實機驗證分開記錄。無法執行的平台／桌面／音訊硬體測試標示 REQUIRES MANUAL VALIDATION，不以合成測試或建置成功代替主觀播放與同步驗證。

交付包含變更清單、測試結果、效能原始數據與限制。尚未獲授權推送、合併、改版號或發布；本設計不執行上述動作。
