# OpenCam v1.3.0 驗證紀錄

日期：2026-11-13。程式與套件來源：`cbe3270e65cbeaf2d9fff87883c0614d5ad5c08e`。

[三平台建置與驗證](https://github.com/kaoshou/OpenCam/actions/runs/43362677384) 的 12 個驗證、建置及安裝工作全部成功。該次為 build-only，發布工作依設定略過。發布使用此輪同一提交的產物，另執行既有來源、整併及不可覆寫上傳檢查，沒有重新編譯後混用不同輪次的程式包。

## 修正與證據

- 執行環境採 .NET 10 LTS：SDK `10.0.404`、內附 runtime `10.0.15`。所有專案、探針及正式建置路徑改為 `net10.0`。保留 C# 12 語意，避免升級編譯器後改變既有 Span 多載選擇。使用者不須另裝 .NET。
- macOS 套件最低需求與文件一致為 macOS 15、Apple Silicon，依據 [.NET 10 支援系統表](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)；未新增 Intel Mac 或 Windows ARM64 套件。
- 關閉的主視窗模型解除全域語系事件訂閱。回歸測試在修正前觀察到已清理模型仍收到 152 次通知，修正後為零；仍開啟的模型正常更新。
- UI 測試使用隔離設定，語系變更與還原在 Avalonia 測試生命週期內完成。保留原有拖曳、修剪、註記與焦點斷言。
- Linux 授權檔從正式 publish 當下保留的資產快照，選取精確版本的 runtime。新舊快取並存、缺檔、錯誤 RID／版本及後續探針 restore 的情境有回歸檢查；實際套件的兩份授權檔與上游 `10.0.15` 套件逐位元組相同。
- Windows 媒體工具的舊 zlib 來源網址回傳 404，改採[官方 zlib 1.4 與公布的 SHA-256](https://zlib.net/)，另通過其 13 項上游 CTest。OBS／libobs 版本及錄影核心程式未變。
- 來源收集曾在 Node HTTP parser 中止，改用有逾時、HTTPS 限制及重試的 curl，仍保留下載後的精確 SHA-256 檢查。真實來源收集及 HTTPS 正常／內容被改動的回歸測試通過。

## 實際套件與媒體

- Mac 最終 DMG 在本機通過映像 CRC、ad-hoc 簽章完整性、版本、來源提交及 runtime 授權檢查。這不是 Apple Developer ID 簽章或公證。
- 使用該 Mac 套件內的原生 helper，以生成訊號分別錄製無音訊、系統音訊、麥克風、混音四種模式，每種至少五分鐘、20 FPS。四種皆通過 MKV／MP4 全檔解碼、串流數量、有效時長與單調封包時間檢查；MP4 影音尾端時間差最大約 31.5 ms。此數值是封包時間差，不是實體裝置或主觀唇音同步量測。
- Linux 使用 Xvfb／PulseAudio 虛擬桌面與音源，走正式專案服務完成錄音確認、混音播放、暫停續錄、串流剪輯預覽、教鞭與註記、五分鐘 30 FPS 及 20 FPS 對照、MKV／MP4 封包與動態畫面／解碼檢查。
- `.deb` 在乾淨 Ubuntu 24.04／25.04 容器通過相依套件、ELF、可見視窗啟動、移除／重裝資料保留及免安裝版相依修復檢查。25.04 是歷史相容性紀錄；該系統已終止支援，仍以 24.04 LTS 為主要測試目標。
- 五個程式包、完整來源包與共同校驗檔共七個附件。整併前驗證各來源封裝與 Linux 原始校驗資料，整併後再檢查共同 SHA-256；公開前逐檔核對 GitHub 上傳雜湊。

## 未在本輪實測

以下維持 **REQUIRES MANUAL VALIDATION**，不能從短錄、生成訊號或完整解碼成功推定為通過：
