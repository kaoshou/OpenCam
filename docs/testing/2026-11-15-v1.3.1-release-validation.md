## 發布檢查失敗及修正紀錄

- 第一輪 Linux 封裝被舊 Windows/macOS 來源凍結基準攔下。已更新至先前審查且通過兩平台實際匯出／取消測試的精確提交 `1339711d36fc33256c6396c4c486e9a07fed321b`，並移除專案目標版本的忽略例外；原生核心的獨立原始基準檢查保留。37 項相關檢查通過。
- 下一輪遇到兩項測試時序問題。獨立程式於第 1,104 次重現 Avalonia.Headless 11.2.5 `StartNew` 回傳內部 `_dispatchTask` 為 null，隨後 `Dispose` 拋出相同 NullReferenceException；[上游程式碼](https://github.com/AvaloniaUI/Avalonia/blob/11.2.5/src/Headless/Avalonia.Headless/HeadlessUnitTestSession.cs) 在建立 Task 的委派中擷取該變數。測試改用框架管理的 assembly session，每次 Dispatch 的應用程式服務清理與原斷言均保留。
- 音訊測試原本把啟動進度確認視為音量 metadata 已到達。改為在原有 15 秒期限內等待實際 Live 樣本，保留 RMS、輸出及停止驗收，不以固定延遲或略過代替驗證。兩項測試調整未修改正式程式碼；14 項針對性測試與上述最終完整 CI 均通過。
- 失敗工作流程保留：[舊隔離基準](https://github.com/kaoshou/OpenCam/actions/runs/43612216050)、[測試時序問題](https://github.com/kaoshou/OpenCam/actions/runs/43613545085)。本次未發布標籤的原指向另存於本機稽核資料，沒有覆蓋既有 Release 附件。
