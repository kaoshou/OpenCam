# 錄影前音訊平衡

## 使用方式

在錄影前音訊確認，以「系統聲音」與「麥克風」滑桿調整收錄音量。100% 保持原音量，0% 收錄為靜音，不會取消該音源，也不會修改電腦的播放／輸入音量設定。首次使用兩者皆為 100%。

播放教材並用平常說話音量說幾句話，先降低較大的那個音源，再按「測試聲音 5 秒」及「播放混音」。建議使用耳機。混音總量表為實際混合後量測，接近滿幅時會提示降低音量；這不是自動音量修正器。

調整後會停止並重新初始化音訊檢查；快速拖曳會合併更新，停下約 300ms 後開始套用。套用完成前不可確認開始或播放舊試錄。來源量表在拖曳期間顯示新音量的衰減估算，混音總表不沿用舊量測冒充新結果。改過音量須重新試錄；試錄及封存期間禁止調整。

「恢復原音量」將兩者重設為 100%。確認並開始錄製後記住設定，取消不保存；錄製啟動失敗也不撤銷已確認的偏好。略過預檢與暫停續錄沿用保存的音量，不修改既有片段。

本功能不分軌，錄影仍保存混合音軌。五秒試錄只供檢查，不會加入專案。沒有即時耳返或放大增益。預檢仍是既有音訊工具，正式螢幕錄影仍是 libobs，沒有新增舊錄影核心或 fallback。

## 相容性

設定檔缺少音量欄位時使用 100%，數值限制 0～100。非原音量的請求使用 helper 協定 2；舊 helper 會在開始擷取前拒絕，不會悄悄忽略音量。更新時必須使用同一包的新程式與 helper，不可只替換其中一個執行檔。

## 人工驗收矩陣（Windows 與 macOS 分別執行）

前提：使用新建置的完整程式與 helper，耳機、可播放測試聲的應用及可用麥克風；記下版本／commit、裝置與系統。保留既有專案備份。

| 測試 | 步驟 | 預期結果 | 失敗條件與證據 |
|---|---|---|---|
| 雙音源 | 兩來源皆開啟，100/100、25/100、100/25 分別試錄回放並正式錄製 | 被調低來源確實較小，預檢和正式錄影比例一致 | 比例錯誤／另一來源一起改變；提供日誌、設定值及非私人測試片 |
| 單音源／無音源 | 系統單獨、麥克風單獨、皆不選分別開始 | 未選滑桿停用，不意外收進未選來源；無音源仍能錄影 | 無法開始／收錯來源；日誌與來源選取狀態 |
| 0%／正常靜音 | 選音源但設 0%，再測無聲音開始、播放聲音、停止、恢復 | 保留音源健康監測，正式軌為靜音，不誤報故障 | 0% 不能開始或靜音被當裝置故障；日誌及媒體檢查 |
| 試聽不回授 | 試錄後播放，再停止、重新試錄 | 播放時不重收試錄，無無限回授／擷取殘留 | 回音疊加或卡死；日誌，避免用喇叭回收外部聲音混淆判定 |
| 連續操作 | 快速拖曳後立即取消；試錄剛按下時試圖改音量；重開確認 | 取消不保存，試錄中滑桿停用，舊試錄失效，最後值正確 | 過期值覆蓋／舊試錄可播放／視窗無法關閉；操作順序與日誌 |
| 保存 | 確認一組音量後重開；另改一組後取消，再重開 | 沿用已確認值，不保留取消值 | 設定遺失；設定檔音量欄位（勿提供私密路徑） |
| 續錄與同步 | 30fps 至少五分鐘，途中多次暫停續錄；另做 20fps 對照 | 音量一致，畫面／音訊不中斷錯位；MKV 和 MP4 可完整解碼、實際回放 | 音畫漂移、爆音、漏音、資料損毀；日誌、ffprobe 時間軸與 decode 結果 |
| 真裝置故障 | 將所選來源設為 0%，拔除 USB 麥克風／切換端點 | 故障仍可提示；既有錄影保全，不把真故障當正常靜音 | 假裝健康或遺失已有片段；日誌、工作檔、專案狀態 |

合成音訊與自動化 UI 測試不代表以上實體錄影情境已通過；各平台尚未實際執行者一律標為 REQUIRES MANUAL VALIDATION。
