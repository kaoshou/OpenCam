OpenCam 1.1.0 — Windows 影片匯入測試版（非正式 Release）

完整解壓縮到新的資料夾，再執行 OpenCam.exe。不要覆蓋舊版本或修改 obs-runtime 內的檔案。
此包只包含 libobs 新螢幕錄影核心，不包含舊 FFmpeg 螢幕錄影引擎或 OpenCam.ScreenCapture.exe。
新核心無法啟動時會停止並回報，不會改用 GDI；正式版未變更。FFmpeg 保留給聲音試聽、剪輯及匯出。
不需要安裝 OBS Studio，也不需要另裝 .NET。

設定：
1. 設定 → 畫面擷取只有自動。舊 GDI／桌面擷取設定不會生效，不需要刪除設定檔。
2. 首次開啟預設 20 FPS；已儲存的其他 FPS 保留。先用 20 FPS、標準畫質、編碼器自動，選擇要錄的單一螢幕；需要時再比較 30 FPS。
3. 音源依需求開啟，先用短片確認，再測試較長內容；暫勿用於唯一一次的重要錄影。
4. 舊核心建立的專案仍可剪輯與匯出，但不能在本包繼續錄製舊工作階段；請建立新錄影專案。

建議測試：
本次加入影片功能：
1. 新增錄製專案，進入「編輯錄製內容」，按左側「加入影片」，選擇 MP4／MOV／MKV；也可將影片拖入左側片段區。
2. 可一次選擇多部影片。成功後依檔案選取器提供的順序加到結尾，以原檔名命名；轉換及驗證時請等待，或按「取消」。
3. 播放檢查畫面方向與聲音，再測試分割、修剪、排序、音量、復原及重做。錄影片段也應能與加入的影片一起使用。
4. 儲存並關閉專案。將外部原影片改名，再重開專案；加入的片段仍應可以播放。原檔不會被修改，專案使用自行保存的素材。
5. 分別以 20 FPS／30 FPS 專案輸出 MP4，確認片段交界、畫面順序與音畫同步；也請測試網頁播放器輸出。
6. 加入較長影片時取消，確認已有片段保持不變，完成取消後可以繼續操作。加入損毀影片時應提示失敗，原有專案仍可使用。
7. 目前支援單一影片軌、零或一條音軌，寬高各不超過 4096 像素。多音軌及 PQ／HLG HDR 會提示無法加入。內嵌字幕不自動匯入，可另加 SRT／VTT。
8. 請回報來源格式、編碼、尺寸、音軌數、是否直式／手機影片，及失敗發生於加入、預覽或匯出階段；附上當天 app 日誌即可，無需提供私人影片。

本次螢幕註記與工具列測試：
1. 錄影後按 F11 開啟／隱藏工具列，重複操作至少 10 次，確認寬度不會縮小、按鈕不被截斷。可拖曳標題區移動工具列。
2. 按 F10 開啟畫筆，按住左鍵繪圖；再按 F10 回到一般操作，已畫筆跡保留。Esc 在繪圖畫面或工具列有焦點時結束繪圖並清除筆跡。
3. 畫筆／直線／方框／圓圈預設為 Ctrl+Shift+F1／F2／F3／F4。可到「設定 → 全域快捷鍵 → 螢幕註記快捷鍵」更改；變更後請重新測試。
4. 在繪圖中多次切換顏色、粗細與圖形，確認每次點選工具列都能操作，不會誤畫到工具列後方。
5. 選橡皮擦後按住左鍵拖曳，碰到的整筆註記會移除；按「復原」可還原整次拖曳移除的筆跡。
6. 將滑鼠停在工具列按鈕上，確認顯示說明文字；切換繁體中文、英文、日本語，確認版面及提示正常。
7. 主畫面仍可勾選「停止錄影後自動輸出 MP4」。停止後播放 MP4，確認畫面、聲音與螢幕註記都有正常錄入。
新設定的錄影快捷鍵為 Ctrl+F9 開始／停止、F9 暫停／繼續；已有自訂快捷鍵以設定畫面為準。
Windows 全域快捷鍵不使用系統保留的 F12。若快捷鍵已被其他程式占用，請依提示改鍵。
工具列與筆跡可能錄入影片；可先移動或隱藏工具列。原生桌面點擊、混合 DPI 與實際錄影效果仍需本機確認。

本次另包含編輯器及網頁播放器修正：
1. 調整並確認自訂矩形選區後錄影，再關閉／重開程式；不再按「調整選區」應仍可直接錄製同一有效選區。若舊設定已超出單一螢幕，需依新提示重選一次；不要為了通過啟動而錄錯畫面。
2. 在片段屬性持續輸入名稱（包含中文組字），停頓後接著輸入；確認不閃白、不失去焦點、不被舊文字覆蓋，重開專案後名稱仍正確。
3. 錄影中嘗試關閉視窗，確認「返回錄影」文字置中，按下後繼續錄影。
4. 匯出不含字幕的網頁播放器，確認不顯示逐字稿頁籤；有字幕時仍可搜尋與下載逐字稿。
5. 網頁鍵盤說明不再重複三個導覽連結；Windows Chrome／Edge 用 Alt+C／L／T 定位播放器／章節／逐字稿（Firefox 加 Shift，有字幕才提供 T）。
6. 鍵盤說明依 Windows Chrome／Edge、Firefox、macOS 分欄，窄視窗自動換行；頁尾英文顯示 Created with OpenCam，其他語言加上當地語言版本，兩個 OpenCam 都可點選。

本包調整 Windows 系統聲音靜音時的啟動與持續擷取；保留 libobs/WGC，未加入舊錄影核心備援。
系統音訊沿用預檢的「預設多媒體輸出」端點。錄影中切換預設輸出或移除裝置會回報並保留工作檔，請停止確認後重新開始。
開始前不用播放任何聲音。分別測試「雙音源但系統靜音」、「僅系統聲音且靜音」、「僅麥克風」、「不錄音」。
錄製中播放、停止、再播放聲音，確認靜音時不出現音源異常，聲音恢復後仍正常收錄。
預檢取消後重試、以設定中的「暫停／繼續」快捷鍵多次暫停續錄、首次開始失敗後重試，也請檢查。
先錄 30–60 秒：靜止畫面開始、移動教鞭、播放有聲動態影片，停止後檢查預覽與匯出 MP4。
再測試 5 分鐘，以及暫停／繼續；確認開始、中間與結尾的音畫同步與畫面是否流暢。
若出現黑畫面、沒有聲音或錯誤，先停止並保留整個專案，不要刪除 MKV。

請回報：
使用的 FPS、編碼器、音源、擷取範圍，卡頓／音畫秒差是否改善，預覽與 MP4 是否相同。
檔案總管輸入 %LOCALAPPDATA%\ScreenRecorder\Logs，附上測試當天 app-日期.log。
不需要上傳私人錄影或聲音。日誌中的 "RecordingCore":"libobs-v1" 可確認實際使用新核心；
啟動失敗時請提供 "Recording native startup" 及錯誤碼附近的紀錄，內含畫面尺寸、音源是否就緒與啟動階段。
移除舊核心不代表所有實體電腦的啟動問題已解決；本包不會以假影格、假音訊或放寬期限掩蓋失敗。

原生核心需要 Microsoft Visual C++ x64 執行階段；若缺少，請從 Microsoft 官方安裝，
不要從其他網站下載個別 DLL。未能啟用新核心時不會假稱新核心測試成功。
這是實機驗收包；自動測試通過不等於此電腦已完成長時間錄影驗收。
不需要獨立顯示卡或硬體影片編碼器，CPU 編碼仍需正常的 Windows 圖形驅動與桌面環境。
不同 CPU、解析度及同時執行的程式會影響流暢度，不保證所有電腦都能達到 1080p／30 FPS。
