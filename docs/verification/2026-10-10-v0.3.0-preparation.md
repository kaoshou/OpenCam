## Follow-up: Windows CI startup and draft checks

Run 37962459430 at 76be620 failed `verify-windows`; the Windows build was
skipped. The website deployment at the same commit succeeded.

- `DraftWriteFailurePreservesPreviousCopy` expected only `IOException`, but Windows
  rejected replacement of a directory with `UnauthorizedAccessException`. The
  assertion now permits that Windows-specific outcome and still checks that the
  previous draft sequence survives. Production path protection is unchanged.
- `CompletedRecording_RespectsWorkingFileCleanupPolicy(false)` timed out during
  encoder startup even though the collected stderr tail contained progress frames.
  The reader used synchronous `StreamReader.EndOfStream` and was initially queued
  via `Task.Run`. It now starts directly and uses cancellable `ReadLineAsync` to
  detect EOF without occupying a worker waiting for more pipe data. The existing
  first-frame requirement, timeout and failure handling are retained.
- The new progress-reader test failed against the old loop specifically because
  it attempted a synchronous read. After the change, the targeted startup/actual
  recording tests passed (25 passed, 6 skipped), and Core passed all 205 tests.
- Full local Release solution test after the fix: Core 205 passed; Media 652
  passed, 20 skipped, 0 failed. The skipped device/platform checks are not passes.
- Read-only review found no blocking issues in this scoped fix. The deterministic
  test proves removal of a blocking-read hazard, not the precise scheduling cause
  of the original Windows timeout. Windows CI and physical acceptance remain
  necessary; no claim is made that the intermittent issue is conclusively solved.
