# OpenCam 1.0.0 startup preparation

Status: scoped implementation and automated verification complete; not a release approval.

## Scope

- Concurrent initialization of selected independent preflight system/microphone sources. Both are joined before any cleanup; no new trial ownership or media timestamp scheme.
- Audio-only FFmpeg progress interval 100 ms, retaining positive media-progress acknowledgement. This reduces reporting latency, not hardware initialization time. Slightly more local progress messages are expected during audio checks.
- Structured elapsed-time stages: audio sources ready / audio confirmed, recording factory validation / launch validation / encoder selection. No audio content or device identifiers are added to these records.
- 1.0.0 version metadata, clearer preparation wording in Traditional Chinese/English/Japanese, OBS attribution in About and package notices. Preserve the compact audio-check dialog geometry and existing scroll behavior.

## Decisions

- Keep runtime hash validation, first-frame/output and selected-audio checks intact. Do not introduce a cache that could trust changed binaries.
- Keep current encoder selection and trial stop/reopen ownership until native capability selection/shared audio sessions have independent verification.
- OBS recording and standalone FFmpeg media processing remain separate responsibilities. This patch does not remove compatibility code from general developer builds or change native-only packaging selection.
- Version 1.0.0 is preparation metadata, not evidence that long-duration, physical Windows or release gates passed.

## Physical acceptance still required

On Windows and macOS, compare cold start and three warm starts with the same display, encoder and 20 FPS. Exercise no audio, microphone, system audio and both. Save logs containing the new stage timings. Confirm audible trial playback, recheck, cancellation, start, pause/resume, stop, editor preview, MP4 duration/audio/video and synchronization. Compare actual startup elapsed time rather than time spent by the user in the check dialog.

For device-loss tests, unplug or switch an external device while preparing and verify no late-running process or false recording state. Preserve generated media. Do not delete original MKV files to simplify verification.

Publication additionally requires corresponding-source availability for both OBS runtime dependencies and standalone FFmpeg, native package validation, recovery/fault-injection and required long-duration acceptance. Do not label these passed without evidence.
