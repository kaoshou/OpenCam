# 自訂選區重新啟動與播放器說明／頁尾修正

基底：`f505bd1e8eae0b7cc78de69e4d23d8fed21aeeaf`；版本維持 1.0.0。依使用者要求建置 Windows 開發測試包，不合併主分支、不發布 Release。

## 選區證據與修正

已用可控制延遲的設定服務重現：一次選區更新會在前一筆設定仍未完成時觸發 5 筆額外並行儲存，包含 X／Y／寬／高中途快照。舊程式使用 Task.Run，且 SettingsService 共用同一個暫存檔，不能保證最後寫入的就是最後選定的矩形。測試實測進入服務的筆數為 6，修正後前筆未完成時只有 1 筆，完成後僅再寫入一份完整選區快照。

另重現：自訂模式載入後會保留預設螢幕 0，而未恢復已儲存的螢幕 1。原生來源選擇主要依實際矩形而非此 UI 索引，所以不能把索引問題單獨宣稱為錄影失敗的已證實根因。

使用者截圖只有通用來源不可用錯誤，未提供這次的完整顯示邊界／設定及啟動日誌。因此上述是已驗證的程式缺陷及與現象吻合的解釋，不宣稱已在該 Windows 電腦重現唯一根因。

變更：

- 選區資料組成單一設定快照；主畫面的設定儲存按呼叫順序串接，取消不受控的背景並行寫入。
- 一般關閉等待最後設定保存完成。重入關閉仍重新檢查錄影／專案保護，不因偏好儲存授權而關閉正在錄製的工作。
- 自訂與螢幕模式都恢復已儲存的螢幕索引；Windows 重新選區時更新所屬螢幕，macOS 保留原來的明確選區調整／單螢幕限制。
- 錄製前確認舊選區位於唯一一個目前螢幕內、尺寸為有效偶數。失效時在音訊預檢及正式錄影前以三語提示重新確認，不改錄其他螢幕、不裁掉使用者未確認的區域、不加入舊核心備援。
- 已保存為無效區域的舊設定需要重選一次；有效的保存區域應可重開程式後直接開始。尚待使用者 Windows 實機驗收。

## 播放器

- 長段 Accesskey 說明改為 Windows Chrome／Edge、Windows Firefox、macOS 三個平台區塊；使用可換行的格狀排版利用完整可用寬度。
- 快捷鍵目的地獨立一列，補充說明獨立一段；手機／平板自然改為少欄或單欄，不改變原生 Accesskey 行為。
- 頁尾固定包含英文 `Created with OpenCam`；非英文另加當地語言版本。繁中為 `以 OpenCam 製作 ‧ Created with OpenCam`，兩個 OpenCam 均連到專案網址。切換介面語言立即更新，無需重載影片。

## 驗證

- 缺陷前：5 項選區測試均失敗（並行設定快照、載入索引、3 種失效區域未攔截）。修正後同組通過。
- 再加入真實 Avalonia 視窗關閉等待測試；相關選區／設定／首頁／原生來源選擇共 40 項通過，無略過。
- 播放器單元測試 39 通過；完整瀏覽器回歸 23 通過、1 明確略過、0 失敗。略過仍為 macOS CDP 原生 Accesskey 激發限制，非本輪改動，先前已另用桌面原生輸入驗證。三語頁尾及兩個超連結均以真實 DOM 驗證。
- 實際瀏覽器證據：`/tmp/opencam-region-help-final-20261025/results.json`；桌機／平板／手機截圖在同資料夾的 `screens/accesskey-platforms-*.png`。

- 本次未修改 libobs、編碼、音訊或 MP4 媒體處理，不把合成／Headless 測試當成使用者 Windows 實機錄影驗收。
